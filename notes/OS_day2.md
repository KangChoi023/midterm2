## Day 2 — 프로세스와 자원의 하루

### 1교시 · 프로세스의 일생

**키워드**: `프로세스`, `PID`, `PPID`, `R · S · Z`, `좀비`, `고아`

**개요**: 프로세스 = 실행 중인 프로그램 + OS 장부(프로세스 표)의 한 줄. 대부분은 S(잠듦). 좀비는 Memory 가 아니라 부모가 아직 찾아가지 않은 "표의 한 줄".

**핵심 용어**
- **프로세스(process)**: 실행 중인 프로그램. OS 의 프로세스 표에 한 줄(PID · PPID · 상태 · 종료값)로 적힌다
- **PID / PPID**: 프로세스 번호 / 부모의 번호
- **좀비(zombie, Z)**: 종료했지만 부모가 `wait()` 로 종료값을 회수하지 않아 표에 남은 줄
- **고아(orphan)**: 부모가 먼저 죽은 프로세스. PID 1(systemd)이 입양해 대신 회수

**핵심 내용**

#### 상태 글자
> R = 실행 중 + 실행하고 싶음(줄서기) · S = 잠듦 · Z = 좀비
- **대부분 S** → 일이 올 때까지 잠들어 있다

#### 좀비 = 안 찾아간 성적표
> Memory · CPU 는 즉시 회수, 남는 건 "PID 1234, 종료값 7" 한 줄
- **부모 `wait()`** → 성적표 회수 → 표에서 삭제
- ⚠ 부모가 안 찾아가면 Z 가 쌓여 표가 가득 찬다
- **부모가 먼저 죽으면** → PID 1 이 입양해 대신 `wait()`

### 2교시 · fork()

**키워드**: `fork()`, `복제`, `반환값`, `독립 Memory`, `Copy-on-Write`

**개요**: `fork()` 는 프로세스 복사기 — Memory 전체와 CPU 레지스터(PC 포함)를 복제해 자식도 fork 직후부터 달린다. 딱 하나 다른 것이 반환값: 부모는 자식 PID, 자식은 0.

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `fork()` | `pid_t pid = fork();` | 자신을 복제한 자식 프로세스 생성. 부모 ← 자식 PID, 자식 ← 0 |

**핵심 내용**

#### 한 번 호출, 두 번 반환
> 반환값 한 칸이 `if (pid == 0)` 의 갈림길
- **복제되는 것** → Memory(코드 · 변수) · 레지스터(PC 까지) · 파일 핸들 등 장부 대부분
- **다른 것** → 반환값 레지스터 하나 (부모: 자식 PID, 자식: 0)

#### 복제 이후는 남남
- **fork 전 x = 10, 자식이 x = 99** → 부모의 x 는 **10** — 서로 다른 Memory
- **Copy-on-Write** → 실제로는 같이 보다가 "쓰는 순간"에만 그 페이지 복사

### 3교시 · execve()와 wait()

**키워드**: `execve()`, `변신`, `wait()`, `회수`, `fork → execve → wait`

**개요**: `execve()` 는 변신 — Memory 를 철거하고 새 프로그램을 적재한 뒤 PC 를 첫 줄로. 되돌아갈 곳이 없어 성공하면 돌아오지 않는다(PID 는 유지). `wait()` 는 자식의 성적표를 회수. Shell 의 3박자 = fork → execve → wait.

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `execve()` | `execve(path, argv, envp);` | 현재 프로세스를 새 프로그램으로 교체. 성공하면 돌아오지 않음, 실패만 −1 |
| `wait()` | `pid_t w = wait(&status);` | 자식 종료까지 잠들었다가 종료값 회수 |

**핵심 내용**

#### execve = 철거 · 적재 · PC 재설정
> 성공한 execve 는 돌아오지 않는다
- **① 철거** → 기존 코드 · 데이터 삭제
- **② 적재** → 새 프로그램(예 `ls`) 코드
- **③ PC 재설정** → 새 프로그램 첫 줄 — 다음 줄은 영원히 미실행
- **PID 유지** → 몸은 바뀌어도 장부의 같은 줄

#### wait = 잠들었다 성적표 받고 깨기
- 부모 `wait()` → S → 자식 `exit(7)` → 좀비 → OS 가 부모 깨움 → 회수 · 표 삭제
- **이미 좀비가 있으면** → 잠들지 않고 즉시 회수

#### Shell 의 3박자
> bash: fork(복제) → 자식 execve(변신) → 부모 wait(회수) → Prompt 복귀

### 4교시 · CPU 나누기 ①

**키워드**: `스케줄러`, `O(n)`, `O(1)`, `비트맵`, `active / expired`

**개요**: 다음 차례를 고를 때 모든 task 를 훑으면 O(n) — task 가 늘수록 OS 가 느려진다. O(1) 스케줄러는 우선순위 140줄 비트맵 + active/expired 두 배열 교체로 선택을 연산 2회로 만들었다.

**핵심 용어**
- **스케줄러(scheduler)**: 실행할 다음 프로세스(task)를 고르는 OS 부분

**핵심 내용**

#### O(n) — 정직하지만 비싸다
- **매번 전부 훑기** → goodness = counter + priority 최고가 다음 주자
- ⚠ task 1,000개 → 비교 1,000회, 고를 때마다

#### O(1) — 훑지 않고 계산
> 선택 = find-first-bit 1회 + 큐 머리 꺼내기 1회
- **우선순위 140줄 + 비트맵** → 최고 우선순위 줄을 비트 하나로 찾음
- **active / expired** → 시간 다 쓴 task 는 expired 로, active 가 비면 포인터 두 개 맞바꾸기

### 5교시 · CPU 나누기 ②

**키워드**: `CFS`, `vruntime`, `nice`, `레드블랙 트리`

**개요**: CFS 의 규칙은 하나 — "받은 시간(vruntime)이 가장 적은 task 가 다음 주자". 우선순위(nice)는 시계가 오르는 속도, 반응성은 잠꾸러기 기상 보정으로 따라 나온다. 최솟값을 빨리 찾으려고 레드블랙 트리.

**핵심 용어**
- **CFS(Completely Fair Scheduler)**: vruntime 최소인 task 를 고르는 Linux 기본 스케줄러
- **vruntime**: task 마다 "받은 실행 시간" 시계
- **nice**: 우선순위 값. 낮을수록(−) 중요 — 시계가 천천히 올라 더 자주 뽑힘
- **레드블랙 트리(red-black tree)**: 스스로 균형 잡는 이진 탐색 트리. 삽입 · 삭제 · 최솟값 O(log n)

**핵심 내용**

#### 시계 하나로 공평
> 다음 주자 = vruntime 최소(트리의 맨 왼쪽)
- **달리면** → 시계가 올라 뒤로 밀림
- **nice −5** → 시계가 느리게 → 같은 실시간에 더 자주 → 받은 실시간 약 2배
- **잠에서 깬 task** → vruntime 을 최솟값 근처로 보정 (몰아받기 방지 + 즉시 반응)

#### 레드블랙 트리
- **균형 도구** → 색 바꾸기 + 회전
- **규칙 맛보기** → 빨간 노드의 자식은 빨강일 수 없다

### 6교시 · Memory 배급

**키워드**: `buddy`, `split`, `merge`, `XOR`, `slab`, `내부 단편화`

**개요**: buddy 는 2의 거듭제곱 블록을 반씩 쪼개 주고(split) 짝(buddy)이 비면 합친다(merge). slab 은 buddy 의 4KB 페이지를 작은 객체 크기로 재단해 파는 소매점.

**핵심 용어**
- **buddy 할당자(buddy allocator)**: 2의 거듭제곱 크기 블록만 다루며 쪼개고 합치는 페이지 할당자
- **내부 단편화(internal fragmentation)**: 요청보다 크게 줘서 블록 안에 생기는 낭비 (20K 요청 → 32K)
- **slab 할당자(slab allocator)**: 페이지를 같은 크기 객체로 나눠 반복 할당 · 해제를 빠르게 하는 커널 할당자

**핵심 내용**

#### buddy — 반으로 쪼개고 XOR 로 짝 찾기
> buddy 주소 = 내 주소 XOR 내 크기 — 검색 없이 계산 한 번
- **할당** → 20K 요청 → 32K 지급, 큰 블록을 반씩 쪼개 내려감 · 크기별 free list
- **해제** → buddy 가 free 면 병합, 위로 연쇄

#### slab — 도매 페이지를 소매로
- **buddy(도매)** → 4KB 페이지 단위
- **slab(소매)** → 페이지를 64B · 128B 객체로 재단
- **진열대** → partial(새 할당 1순위) · full · empty(반납 후보)

### 7교시 · 가상 메모리

**키워드**: `가상 주소`, `PGD`, `PTE`, `offset`, `TLB`, `CR3`, `Page Fault`, `SIGSEGV`, `LRU`

**개요**: 주소는 값이 아니라 경로 — 32bit 주소 = PGD 10 + PTE 10 + offset 12. 프로세스마다 자기 표(CR3)가 있어 같은 주소도 다른 물리 frame(격리). 아직 안 올라온 페이지는 Page Fault 로 채우고, 내 땅이 아니면 SIGSEGV. RAM 이 모자라면 근사 LRU 로 회수.

**핵심 용어**
- **가상 메모리(virtual memory)**: 프로세스마다 독립된 주소 공간을 주고 표로 물리 주소에 연결하는 방식
- **페이지 테이블(PGD · PTE)**: 가상 주소를 물리 frame 으로 바꾸는 2단 표
- **TLB**: 주소 변환 결과를 담는 캐시 — 표 걷기를 생략하는 지름길
- **Page Fault(#PF)**: 접근한 페이지가 아직 RAM 에 없을 때(P = 0) 발생 → OS 가 채우고 재시도
- **SIGSEGV**: 내 주소 공간(VMA)이 아닌 곳에 접근할 때 프로그램을 강제 종료하는 시그널

**핵심 내용**

#### 주소 = 10 + 10 + 12
> [PGD 인덱스 10bit][PTE 인덱스 10bit][offset 12bit]
- **왜 10bit** → 표 한 장도 4KB 페이지: 4KB ÷ 4B = 1024칸 = 10bit
- **walk** → 표 2장 걷기 = RAM 접근 2회 추가 → **TLB** 적중이면 0회

#### 격리와 두 가지 사고
- **CR3** → 프로세스마다 자기 PGD → 같은 가상 주소, 다른 물리 frame
- **P = 0** → Page Fault → buddy 에서 frame 받아 채우고 재시도
- ⚠ **VMA 에 없는 주소** → SIGSEGV — 강제 종료

#### RAM 이 모자라면 — 근사 LRU
- **active / inactive 두 줄 + R비트** → inactive 꼬리부터: R = 1 이면 기회 한 번 더, R = 0 이면 축출(dirty 면 write-back 먼저)
- ⚠ 쫓아낸 페이지를 다시 쓰면 refault — 디스크에서 재적재(수만 배 느림)

### 8교시 · 종합

**키워드**: `ls ⏎ 의 여행`, `6단계`

**개요**: Terminal 의 `ls` 한 줄이 처리되는 전 과정을 여섯 단계로 — 오늘의 모든 세션이 한 번씩 등장.

**핵심 내용**

#### 명령 한 줄의 여행
> fork → execve → CFS → MMU → #PF + buddy → wait
- **① 복제** → bash 가 `fork()`
- **② 변신** → 자식이 `execve("ls")`
- **③ 차례** → CFS 가 CPU 배정
- **④ 주소 변환** → MMU 가 PGD → PTE
- **⑤ 첫 접근** → Page Fault + buddy 로 페이지 적재
- **⑥ 회수** → 부모 `wait()`, Prompt 복귀
