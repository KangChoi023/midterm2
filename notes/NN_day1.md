**핵심 내용**

#### 머신러닝 — 규칙을 데이터에서 찾는다
> 사람이 규칙을 코드로 쓰는 대신, 입력 · 정답 쌍(데이터)을 주고 컴퓨터가 규칙의 **숫자(파라미터)** 를 찾게 하는 방법
- **포함 관계** → AI(인공지능) ⊃ 머신러닝 ⊃ 딥러닝 (딥러닝 = 층을 깊게 쌓은 신경망으로 하는 머신러닝)
- **왜** → "헬멧을 썼는가?" 처럼 말로 규칙을 쓸 수 없는 문제를 풀려고
- **파라미터(θ)** → 찾아낸 숫자 = 모델의 규칙 — 화씨 변환 **2개**(w, b), MNIST 신경망 약 **8만** 개, YOLOv8n 약 **300만** 개

#### 학습 = 최적화 (θ* = argmin L)
> 학습이란 손실 L(예측과 정답의 차이)을 가장 작게 만드는 파라미터 θ 를 찾는 일
- **손실(L)** → 예측이 정답에서 얼마나 먼지를 숫자 하나로 — 작을수록 좋다
- **argmin** → 함수값이 최소가 되는 **입력(위치)** — 최솟값 자체가 아니다
- **학습의 고리** → 모델로 예측 → 손실로 채점 → 기울기로 방향 → 갱신으로 이동 → 반복
- **5일 계획** → Day 1 도구 · Day 2 모델 · 손실 · Day 3 기울기(역전파) · Day 4 갱신 개선 · Day 5 CNN
| 고리 단계 | 하는 일 | 만드는 날 |
|---|---|---|
| 모델 y = f(x; θ) | 입력에 파라미터를 곱하고 더해 예측 | Day 2 |
| 손실 L | 예측과 정답의 차이를 숫자 하나로 | Day 2 |
| 기울기 ∂L/∂θ | 어느 쪽으로 바꾸면 손실이 줄어드나 | Day 1 · Day 3 |
| 갱신 θ ← θ − η∇L | 기울기 반대 방향으로 조금 이동 | Day 1 · Day 4 |

#### 개념 1 · AI ⊃ 머신러닝 ⊃ 딥러닝
세 낱말은 포함 관계다.
- **AI(인공지능)**: 사람의 지적 작업을 기계가 하게 만드는 모든 기술. 사람이 규칙을 짜 넣은 체스 프로그램도 AI 다.
- **머신러닝**: 규칙을 사람이 쓰지 않고, **입력 · 정답 쌍(데이터)에서 찾게 하는** 방법.
- **딥러닝**: 층(layer)을 여러 겹 쌓은 **신경망**으로 학습하는 머신러닝. 이미지 · 음성처럼 말로 규칙을 쓰기 어려운 문제에 강하다. 이 과정의 YOLO · 센서 이상 감지 모델이 모두 여기에 속한다.

##### 🔎 왜 이렇게 되나
- **비유**: AI 는 "탈것", 머신러닝은 "자동차", 딥러닝은 "전기차" — 안쪽일수록 좁고 구체적이다
- **① AI 가 가장 넓은 이유**: 사람이 규칙을 짜 넣은 체스 프로그램도 "지적 작업" 을 하니 AI
- **② 머신러닝이 다른 점**: 규칙을 사람이 쓰지 않고 데이터에서 찾는다
- **③ 딥러닝이 다른 점**: 층을 여러 겹 쌓아, 특징까지 스스로 배운다 — 이미지 · 음성처럼 규칙을 쓰기 어려운 문제에 강하다
- ⚠ "딥러닝 = AI 전부" 가 아니다 — 포함 관계의 가장 안쪽

#### 개념 2 · 규칙을 쓰는가, 데이터에서 찾는가
섭씨를 화씨로 바꾸는 예를 보자.
- **전통 프로그래밍**: 사람이 규칙 `F = 1.8C + 32` 를 코드로 쓴다.
- **머신러닝**: (섭씨, 화씨) 쌍을 잔뜩 주면 컴퓨터가 F = w·C + b 의 **w = 1.8, b = 32** 라는 숫자를 찾는다.

여기서 찾는 숫자 w, b 를 **파라미터(θ)** 라 한다. 신경망의 "규칙" 은 결국 이 숫자들의 모음이다. 화씨 예제는 2개, Day 3 의 MNIST 신경망은 약 8만 개, YOLOv8n 은 약 300만 개다. "헬멧을 썼는가?" 처럼 말로 규칙을 쓸 수 없는 문제가 바로 머신러닝이 필요한 문제다.

##### 🔎 왜 이렇게 되나
- **비유**: 요리법을 직접 쓰는 대신, 완성된 요리 사진(정답)을 잔뜩 보여 주고 요리법(숫자)을 알아내게 하는 것
- **① 규칙을 못 쓰는 문제가 많은 이유**: "고양이 사진 규칙" 은 사람이 코드로 쓸 수 없다 — 하지만 예시는 많다
- **② 찾는 것은 숫자**: F = w·C + b 에서 w = 1.8, b = 32 — 신경망의 "규칙" 도 결국 수많은 w, b (파라미터 θ)
- **③ 그래서 데이터가 중요**: 숫자를 찾을 재료가 입력 · 정답 쌍이기 때문
- ⚠ 데이터에 없는 경우는 모델도 모른다 (VB D1 domain shift)

#### 개념 3 · 학습 = 최적화, 그리고 학습의 고리
> θ* = argmin_θ L(θ) — 손실 L 을 가장 작게 만드는 파라미터 θ 를 찾는 일

- **손실(L)**: 예측과 정답의 차이를 숫자 하나로 나타낸 값. 작을수록 좋다.
- **argmin**: 함수값이 최소가 되는 **입력(위치)** 을 뜻한다. 최솟값 자체가 아니다.

이 일을 실제로 하는 방법이 아래 네 단계를 반복하는 **학습의 고리**다. 5일 과정은 이 고리의 부품을 하나씩 만들어 가는 과정이다.

![학습의 고리 — 모델로 예측하고, 손실로 채점하고, 기울기로 방향을 찾고, 갱신으로 조금 이동하기를 반복한다](assets/fig/nn/d1-learning-loop.svg)

| 단계 | 하는 일 | 만드는 날 |
|---|---|---|
| 모델 y = f(x; θ) | 입력에 파라미터를 곱하고 더해 예측 | Day 2 순전파 |
| 손실 L | 예측과 정답의 차이를 숫자 하나로 | Day 2 MSE · Cross-Entropy |
| 기울기 ∂L/∂θ | 파라미터를 어느 쪽으로 바꾸면 손실이 줄어드나 | Day 1 미분 · Day 3 역전파 |
| 갱신 θ ← θ − η∇L | 기울기 **반대** 방향으로 조금 이동 | Day 1 경사하강 · Day 4 옵티마이저 |

오늘(Day 1)은 이 고리를 돌리는 도구 — NumPy · 행렬 · 미분 — 를 만들고, 8교시에 고리를 처음 직접 돌린다.

##### 🔎 왜 이렇게 되나
- **비유**: 눈 가리고 산에서 가장 낮은 골짜기를 찾기 — 발밑 경사를 느끼며 내려간다
- **① 학습 = 최적화인 이유**: "잘 맞힌다" 를 숫자(손실 L)로 바꾸면, 그 숫자를 가장 작게 하는 θ 를 찾는 문제가 된다
- **② argmin 이 위치인 이유**: 우리가 원하는 건 최솟값 자체가 아니라 그때의 파라미터 θ*
- **③ 학습의 고리 네 단계**: 예측 → 채점(손실) → 방향(기울기) → 이동(갱신) 을 반복 — 5일 동안 이 고리를 하나씩 만든다
- ⚠ 손실이 작다고 끝이 아니다 — 처음 보는 데이터에서도 맞혀야 한다 (Day 4 과적합)

### 2교시 · Python 속성 (C 개발자용)

**키워드**: `변수 = 이름표`, `동적 타입`, `is vs ==`, `id()`, `가변 · 불변`, `b = a 는 공유`, `.copy()`, `참조의 배열`, `/ 와 //`, `a[-1]`, `리스트 컴프리헨션`

**개요**: C 개발자가 Python 에서 가장 많이 틀리는 지점은 **"변수 = 메모리 칸"** 이라는 생각이다. ① Python 의 변수는 heap 의 객체에 붙인 **이름표**이고 타입은 객체에 붙어 있다(동적 타입). ② 그래서 `b = a` 는 복사가 아니라 이름표를 하나 더 붙이는 것 — 리스트 · ndarray 같은 **가변 객체**는 한쪽을 바꾸면 다른 쪽에도 보인다. ③ 리스트의 칸에는 값이 아니라 **참조**가 들어 있어 숫자 계산이 느리다 → 3교시 NumPy 가 필요한 이유.

**한눈에 보기**
Python 의 변수 — 객체에 붙인 이름표
> C 의 변수는 값이 든 메모리 칸, Python 의 변수는 heap 의 **객체를 가리키는 이름표** — 타입도 값이 아니라 객체에 붙어 있다 (동적 타입)
- **`b = a` 는 복사가 아니라 이름표 하나 더**: `is` = 같은 객체인가, `==` = 값이 같은가
- **가변 객체는 제자리에서 바뀐다**: list · dict · ndarray 는 `b.append(4)` 하면 a 도 바뀜 — 독립 사본은 `.copy()`
- **불변 객체는 바뀌면 새 객체**: int · str · tuple — `y = y + 1` 은 y 만 새 객체로 옮긴다
- **리스트는 참조의 배열이라 숫자 계산이 느리다**: 칸마다 객체를 따라가 타입 확인 → NumPy 는 값을 연속 메모리에 둔다 (3교시)
- **C 와 다른 문법**: 들여쓰기가 문법 · `for i in range(n):` · 리스트 컴프리헨션 `[x ** 2 for x in range(10) if x % 2 == 0]`
- **⚠ `7 / 2` 는 3.5, 정수 몫은 `7 // 2` = 3**: `a[-1]` 은 오류가 아니라 마지막 원소

**핵심 용어**
- **이름(name)**: 객체를 가리키는 이름표. `a = 3` 은 int 객체 3 에 a 라는 이름표를 붙이는 것
- **동적 타입(dynamic typing)**: 타입이 변수가 아니라 **객체**에 붙어 있어, 같은 이름이 다른 타입 객체를 가리킬 수 있음
- **가변 객체(mutable)**: 제자리에서 바뀌는 객체 — list · dict · **ndarray**. `b = a` 로 공유된다
- **불변 객체(immutable)**: 바뀌지 않는 객체 — int · float · str · tuple. `y = y + 1` 은 **새 객체**를 만들어 이름표를 옮긴다
- **참조(reference)**: 객체를 가리키는 값. 리스트의 칸에는 값 대신 참조가 들어 있다

**핵심 내용**

#### Python 변수 = 객체에 붙인 이름표
> C 의 변수는 값이 든 메모리 칸, Python 의 변수는 heap 의 **객체를 가리키는 이름표** — 타입도 객체에 붙어 있다(동적 타입)
- **`b = a`** → 복사가 아니라 **같은 객체에 이름표 하나 더**
- **`is` vs `==`** → `is` = 같은 객체인가(id), `==` = 값이 같은가
- **동적 타입** → `x = 3` 다음 `x = "three"` 가 오류 없이 된다, 정수는 크기 제한 없음(`2 ** 100` 도 정확)

#### 가변 · 불변 — 복사 버그의 원인
> 가변 객체(list · dict · ndarray)는 제자리에서 바뀌고, 불변 객체(int · str · tuple)는 바뀌면 새 객체가 생긴다
- **가변** → `b = a` 후 `b.append(4)` 하면 a 도 바뀐다 (같은 객체)
- **불변** → `y = x; y = y + 1` 은 새 객체를 만들어 y 만 옮긴다 → x 는 그대로
- **`.copy()`** → 가변 객체의 독립 사본
- ⚠ Day 3 에서 `W.copy()` 를 빠뜨리면 원본 가중치가 함께 바뀌는 버그

#### 리스트 = 참조의 배열 → NumPy 가 필요한 이유
> 리스트 칸에는 값이 아니라 객체를 가리키는 **참조**가 있어, 유연하지만 숫자 계산이 느리다
- **장점** → 길이 자유, 타입 섞기 가능 (`[3, "a", 2.0]`)
- **느린 이유** → 숫자 하나 더할 때마다 참조 따라가기 → 타입 확인 → 새 객체 만들기
- **해결** → NumPy 는 값을 C 배열처럼 **연속 메모리**에 둔다 (3교시)

#### C 와 다른 문법
> 들여쓰기가 문법이고, 나눗셈 · 인덱스 규칙이 C 와 다르다
- **`for i in range(n):`** → C 의 `for (i = 0; i < n; i++)`
- **리스트 컴프리헨션** → `[x ** 2 for x in range(10) if x % 2 == 0]` → `[0, 4, 16, 36, 64]`
- ⚠ `7 / 2` = **3.5** (항상 실수), 정수 몫은 `7 // 2` = **3**
- ⚠ `a[-1]` 은 오류가 아니라 **마지막 원소**

#### 개념 1 · 변수는 메모리 칸이 아니라 객체에 붙인 이름표
- **C**: `int a = 3;` 은 값 3 이 든 메모리 칸 a 를 만든다. `b = a` 는 값을 다른 칸에 **복사**한다.
- **Python**: `a = 3` 은 heap 어딘가의 int 객체 3 에 **이름표 a 를 붙이는 것**이다. `b = a` 는 같은 객체에 이름표 b 를 **하나 더** 붙인다 — 복사가 아니다.
- 타입도 변수가 아니라 객체에 붙어 있다(동적 타입). 그래서 `x = 3` 다음에 `x = "three"` 가 오류 없이 된다.

##### 🔎 왜 이렇게 되나
- **비유**: C 변수는 "이름이 적힌 상자", Python 변수는 "물건에 붙인 포스트잇"
- **① b = a 가 복사가 아닌 이유**: 같은 객체에 포스트잇을 하나 더 붙일 뿐 — 상자를 새로 만들지 않는다
- **② 타입이 객체에 붙는 이유**: 이름표는 무엇이든 가리킬 수 있다 — 같은 이름이 int 였다가 str 이 될 수 있다(동적 타입)
- **③ 그래서**: 값을 바꾸는 방식(가변 · 불변)에 따라 공유가 보이기도 하고 안 보이기도 한다 (개념 2)
- ⚠ 신경망 코드에서 배열을 "복사했다" 고 착각하면 원본 가중치가 바뀌는 버그가 생긴다

#### 개념 2 · 가변 객체는 공유된다 — is 와 ==
- `is` 는 **같은 객체**인가(id 가 같은가), `==` 는 **값이 같은가** 를 묻는다.
- **가변(mutable) 객체** — list, dict, NumPy 배열 — 는 제자리에서 바뀐다. `b = a` 로 공유한 뒤 `b.append(4)` 하면 a 도 `[1, 2, 3, 4]` 가 된다.
- **불변(immutable) 객체** — int, float, str, tuple — 는 바뀌지 않는다. `y = y + 1` 은 새 객체를 만들어 y 이름표만 옮기므로 x 는 그대로다.
- 진짜 복사본이 필요하면 **`.copy()`**. 이 규칙은 NumPy 배열에도 그대로라, Day 3 에서 `W.copy()` 를 빠뜨리면 원본 가중치가 바뀌는 버그가 생긴다.

| 구분 | 예 | `b = a` 후 b 를 바꾸면 |
|---|---|---|
| 불변 | int, float, str, tuple | a 는 그대로 (b 만 새 객체로) |
| 가변 | list, dict, ndarray | **a 도 바뀐다** (같은 객체) |

##### 🔎 왜 이렇게 되나
- **비유**: 공유 문서(가변)는 누가 고치면 모두에게 보이고, 출력물(불변)은 고치려면 새로 인쇄해야 한다
- **① is 와 == 가 다른 이유**: is 는 같은 객체인가(포스트잇이 같은 물건에 붙었나), == 는 내용이 같은가
- **② 가변이 공유되는 이유**: list · dict · ndarray 는 제자리에서 바뀐다 — 같은 객체를 가리키는 모든 이름에서 보인다
- **③ 불변이 안전한 이유**: int · str · tuple 은 바꾸면 새 객체를 만든다 — 다른 이름표는 옛 객체를 그대로 가리킨다
- ⚠ 독립된 사본이 필요하면 `.copy()` (NumPy 도 같음)

#### 개념 3 · 리스트는 참조의 배열 — 그래서 NumPy 가 필요하다
- C 배열은 값이 메모리에 연속으로 놓인다. Python 리스트의 칸에는 값이 아니라 **객체를 가리키는 참조**가 들어 있고, 객체들은 heap 여기저기에 흩어져 있다.
- 장점은 유연함(길이 자유, 타입 섞기 가능)이지만, 숫자 하나를 더할 때마다 "참조 따라가기 → 타입 확인 → 덧셈 → 새 객체 만들기" 를 반복하니 **숫자 계산이 느리다**.
- 신경망은 수만 ~ 수백만 개의 숫자를 계산한다 → 값을 연속 메모리에 담는 NumPy 배열(3교시)이 필요한 이유.

##### 🔎 왜 이렇게 되나
- **비유**: 리스트는 "물건 위치가 적힌 쪽지 묶음", NumPy 배열은 "물건을 한 줄로 늘어놓은 선반"
- **① 리스트가 느린 이유**: 숫자 하나 더할 때마다 쪽지를 따라가 → 타입 확인 → 덧셈 → 새 객체 를 반복
- **② 리스트의 장점**: 길이 자유 · 타입 섞기 가능 — 유연하지만 숫자 계산엔 비효율
- **③ 그래서 NumPy**: 같은 타입 값을 메모리에 연속으로 두고 C 코드로 한 번에 계산 (3 · 4교시)
- ⚠ 신경망의 숫자는 모두 NumPy 배열로 — 리스트로 계산하면 수백 배 느리다

### 3교시 · NumPy ndarray

**키워드**: `ndarray`, `ndim · shape · size · dtype`, `strides (32, 8)`, `view vs copy`, `np.shares_memory`, `불리언 마스크`, `axis = 없어지는 축`, `keepdims`, `브로드캐스팅`, `오른쪽 축부터`, `(3,) vs (3, 1)`

**개요**: 신경망의 입력 · 가중치 · 출력은 전부 **ndarray** 다. ① ndarray 는 같은 dtype 숫자를 메모리에 **한 줄로** 놓고, shape · strides 라는 "읽는 규칙"으로 다차원처럼 보여 준다 — 그래서 reshape · 슬라이스는 복사 없이 **view** 를 만든다. ② 집계 함수의 **axis 는 "없어지는 축"** 이다. ③ **브로드캐스팅**은 shape 를 오른쪽 끝부터 맞춰 크기 1 인 축을 늘리는 규칙 — 신경망 한 층의 `X @ W + b` 에서 편향이 모든 샘플에 더해지는 원리다.

**한눈에 보기**
NumPy ndarray — 한 줄 메모리 + 읽는 규칙
> 같은 타입의 값을 메모리에 **한 줄로 연속** 놓고, shape(모양) · strides(한 칸 이동 바이트)로 다차원처럼 읽는 배열 — 신경망의 모든 숫자가 여기에 담긴다
- **strides — 옆 칸 · 아래 칸으로 가는 바이트 수**: `arange(12).reshape(3, 4)` (int64) 는 (32, 8)
- **reshape · 슬라이스는 view — 같은 메모리를 다르게 읽을 뿐**: 고치면 원본도 바뀐다, 독립 사본은 `.copy()`
- **`A[행, 열]` 로 고르고 조건식으로 거른다**: `A[:, 1]` 1열 전체 · `A[A > 6]` 조건이 참인 원소만 (Day 3 ReLU 역전파)
- **axis = 모아서 없앨 축**: (3, 4) 에서 `sum(axis=0)` → (4,) · `sum(axis=1)` → (3,) · `keepdims=True` 면 (3, 1) 로 남김
- **브로드캐스팅 — 오른쪽 끝부터 비교해 1 인 쪽을 늘린다**: `X @ W + b` 의 편향 b (H,) 가 모든 샘플에 더해지는 원리
- **⚠ `np.array([1, 2, 3])` 은 int64**: 0.5 를 넣으면 0 으로 잘린다 → `dtype=float` · (3,) 와 (3, 1) 은 다른 shape

**핵심 용어**
- **ndarray**: NumPy 다차원 배열. 같은 dtype 의 값이 **연속 메모리**에 놓여 있다 (C 의 `double a[3][4]` 와 같은 구조)
- **shape**: 각 축의 크기 튜플 — `np.zeros((3, 4))` 는 `(3, 4)`, ndim **2**, size **12**
- **dtype**: 원소 타입 — 정수 리스트는 `int64`, 실수는 `float64`
- **strides**: 각 축으로 한 칸 움직일 때 건너뛰는 **바이트** 수 — int64 (3, 4) 는 `(32, 8)`
- **view**: 메모리를 공유하는 다른 모양의 배열. 슬라이스 · reshape 결과. 고치면 원본도 바뀐다
- **axis**: 집계할 때 **없어지는 축**. `sum(axis=0)` 은 axis 0 이 사라져 열마다 하나
- **브로드캐스팅(broadcasting)**: shape 를 오른쪽 끝부터 비교해 같거나 한쪽이 1 이면, 1 인 쪽을 늘려 계산하는 규칙

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `np.array()` | `np.array([1, 2, 3], dtype=np.float32)` | 리스트 → ndarray |
| `np.zeros()` | `np.zeros((3, 4))` | 0 으로 채운 배열 (`np.ones` 는 1) |
| `np.arange()` | `np.arange(0, 10, 2)` | 범위 배열 (stop 미포함) |
| `np.linspace()` | `np.linspace(0, 1, 5)` | 구간을 n 등분한 점 (끝 포함) |
| `ndarray.reshape()` | `A.reshape(4, 3)` · `A.reshape(-1)` | 모양 바꾸기 — 대부분 view |
| `np.random.default_rng()` | `rng = np.random.default_rng(42)` | seed 고정 난수 생성기 |

**핵심 내용**

#### ndarray — 한 줄 메모리 + 읽는 규칙
> 같은 타입(dtype)의 값을 메모리에 **한 줄로 연속** 놓고, shape(모양) · strides(한 칸 이동 바이트 수)로 다차원처럼 읽는다
- **속성** → `ndim` 차원 수 · `shape` 모양 · `size` 원소 수 · `dtype` 타입
- **strides** → `arange(12).reshape(3, 4)` (int64) 는 **(32, 8)** — 옆 칸 8바이트, 아래 칸 4 × 8 = 32바이트
- **view (`ndarray.reshape` · 슬라이스)** → 같은 메모리를 다르게 읽을 뿐 → 고치면 원본도 바뀐다, 독립 사본은 `.copy()`
- **만들기** → `np.zeros` · `np.arange` · `np.linspace` · 난수는 `rng = np.random.default_rng(42)`
- ⚠ `np.array([1, 2, 3])` 은 **int64** — 0.5 를 넣으면 0 으로 잘린다 → `dtype=float`

#### 인덱싱 · 슬라이싱 · 불리언 마스크
> `A[행, 열]` 로 고르고, `:` 는 "그 축 전체", 조건식은 True 인 자리만 고른다
- **`A[1, 2]` · `A[0]` · `A[:, 1]`** → 한 칸 · 0행 전체 · 1열 전체
- **`A[1:, 2:]`** → 부분 행렬 (view)
- **불리언 마스크 `A[A > 6]`** → 조건이 참인 원소만 — Day 3 ReLU 역전파에서 "막힌 자리" 기억
- ⚠ (3,) 와 (3, 1) 은 다른 shape — 1차원 벡터는 행도 열도 아니다

#### axis — 그 축을 따라 모으고 없앤다
> `sum(axis=k)` · `mean(axis=k)` 는 k 번 축을 따라 모아 **그 축을 없앤다**
- **axis=0** → 위 → 아래로 모아 열마다 하나: (3, 4) → **(4,)**
- **axis=1** → 왼 → 오른쪽으로 모아 행마다 하나: (3, 4) → **(3,)**
- **`keepdims=True`** → 없앤 축을 크기 1 로 남김 (3, 1) → 원래 배열과 다시 계산할 때 필요
- **신경망에서** → 배치 축(axis 0)으로 평균 — 손실 평균 · BatchNorm

#### 브로드캐스팅
> shape 를 **오른쪽 끝부터** 비교해, 각 축이 같거나 한쪽이 1 이면 1 인 쪽을 늘려 계산한다 (실제 복사는 없음)
| 식 | 결과 |
|---|---|
| (3, 4) + (4,) | (3, 4) — 모든 행에 더함 |
| (3, 1) + (1, 4) | (3, 4) — 양쪽이 늘어남 |
| (3, 4) + (3,) | ❌ 오류 — 4 와 3 이 다름 |
- **신경망에서** → `X @ W + b` 의 편향 b (H,) 가 모든 샘플(행)에 더해지는 원리
- **예** → `arange(12).reshape(3, 4) + [10, 20, 30, 40]` → 첫 행 `[10 21 32 43]`

**기본 사용형태**
```python
import numpy as np
rng = np.random.default_rng(42)
A = np.arange(12).reshape(3, 4)      # shape (3, 4), strides (32, 8)
A.sum(axis=0)                        # (4,)  열마다
A.mean(axis=1, keepdims=True)        # (3, 1)
A + np.array([10, 20, 30, 40])       # (3, 4) + (4,) 브로드캐스팅
B = A[1:, 2:].copy()                 # 독립 사본
x = np.array([1.0, 2.0, 3.0])        # 실수 계산은 float 로
```

#### 개념 1 · ndarray = 한 줄 메모리 + 읽는 규칙
ndarray 는 같은 타입(dtype)의 값을 **메모리에 한 줄로 연속** 놓고, 그것을 몇 행 몇 열로 읽을지(shape)와 한 칸 이동할 때 몇 바이트를 건너뛸지(strides)를 함께 가진다.

![12개 값이 메모리에 한 줄로 놓이고, shape (3, 4) 와 strides (32, 8) 로 표처럼 읽힌다](assets/fig/nn/d1-strides.svg)

- `np.arange(12).reshape(3, 4)` 는 int64(8바이트) 12개. strides = **(32, 8)**: 옆 칸은 8바이트, 아래 칸은 4칸 × 8 = 32바이트 이동.
- `A[1, 2]` 는 1×32 + 2×8 = 48바이트 위치의 값 **6** 이다.
- **reshape 은 대부분 view** — 같은 메모리를 다른 shape 로 읽을 뿐이라 복사가 없어 빠르지만, view 를 고치면 원본도 바뀐다. 독립 사본은 `.copy()`.

##### 🔎 왜 이렇게 되나
- **비유**: 구슬 12개를 한 줄로 꿴 목걸이를, "4개씩 3줄" 로 읽기로 약속하는 것 — 구슬은 그대로
- **① 한 줄로 두는 이유**: 연속 메모리여야 CPU 가 빠르게 읽고 C 코드로 한 번에 계산할 수 있다
- **② strides**: 옆 칸 · 아래 칸으로 가려면 몇 바이트 건너뛰나 — (3, 4) int64 면 (32, 8)
- **③ reshape 가 view 인 이유**: 읽는 규칙(shape · strides)만 바꾸고 메모리는 공유 — 그래서 빠르다
- ⚠ view 를 고치면 원본도 바뀐다 — 독립이 필요하면 `.copy()`

#### 개념 3 · 브로드캐스팅 — 모양이 다른 배열끼리 계산하기
(3, 4) 배열에 (4,) 배열을 더하면, 작은 쪽이 **행 방향으로 복사된 것처럼** 늘어나 계산된다. 실제로 복사하지는 않는다.

![(3, 4) + (4,) — b 가 모든 행에 더해진다](assets/fig/nn/d1-broadcast.svg)

- **규칙**: 뒤쪽 축부터 맞춰 보고, 크기가 같거나 1 이면 늘려서 계산한다. 맞지 않으면 오류.
- 신경망의 "+ 편향 b" 가 바로 이것이다: (N, M) 출력에 (M,) 편향을 더하면 모든 샘플(행)에 같은 b 가 더해진다.
- `axis` 를 지정한 집계(`sum(axis=1)`)는 그 축을 없앤다. `keepdims=True` 를 주면 크기 1 로 남겨 다시 브로드캐스팅할 수 있다 — Day 2 softmax 에서 필수.

##### 🔎 왜 이렇게 되나
- **비유**: 반 전체(행마다)에 같은 공지(편향)를 복사해 붙이지 않고 "모두 같은 걸 받은 것처럼" 계산하는 것
- **① 뒤쪽 축부터 맞추는 이유**: 마지막 축이 특징 · 열이라, 행마다 같은 값을 더하는 경우가 가장 흔하다
- **② 1 이면 늘리는 이유**: 크기 1 인 축은 "모두에 같은 값" 이라는 뜻 — 실제 복사 없이 계산
- **③ 신경망에서**: (N, M) 출력 + (M,) 편향 → 모든 샘플에 같은 b
- ⚠ (3,) 와 (3, 1) 은 다르다 — 원하지 않는 방향으로 늘어나면 오류 없이 엉뚱한 결과

### 4교시 · 벡터화

**키워드**: `벡터화`, `C · BLAS`, `원소별 연산`, `@ 행렬곱`, `C[i][j] = 행 · 열 내적`, `(N, D) @ (D, H) → (N, H)`, `for 루프 vs @`, `원소별 곱 *`, `core dimension mismatch`, `axis 집계`, `argmax`

**개요**: 신경망은 곱셈-덧셈을 수백만~수십억 번 한다. ① **벡터화**는 Python for 루프 대신 NumPy 연산 한 번으로 배열 전체를 처리하는 것 — 내부가 C · BLAS 라 수백 배 빠르다. ② 행렬곱 `C = A @ B` 의 한 칸은 **A 의 행과 B 의 열의 내적**이고, 안쪽 차원이 같아야 하며 그 축은 사라진다. ③ `mean` · `sum` · `argmax` 는 axis 로 "무엇을 기준으로" 집계할지 정한다.

**한눈에 보기**
벡터화 — 반복을 NumPy 안으로
> 파이썬 for 루프 대신 배열 연산 한 줄로 쓰면, 실제 반복은 컴파일된 C 코드(BLAS · SIMD)가 하므로 **수천 배** 빨라진다
- **원소별 연산은 배열 전체에 한 번에**: `x * 2`, `x ** 2`, `np.exp(x)`
- **3중 for 행렬곱 vs `@`**: 200×200 에서 `@` 가 수천 배 빠르다 (CPU 마다 다름)
- **`A @ B` 는 (N, D) @ (D, H) = (N, H)**: 안쪽 D 가 같아야 하고 계산 뒤 사라진다 — 신경망 한 층 `X @ W`
- **axis 로 모으고 argmax 로 위치 찾기**: 성적표 (5, 3) 에서 `mean(axis=0)` 과목별 평균 [72.6, 80.4, 78.0] · 총점 1등 = 학생 3
- **⚠ shape 가 같으면 `*` 도 오류 없이 돈다**: 원소별 곱이라 행렬곱과 결과가 다르다 → 행렬곱은 반드시 `@`

**핵심 용어**
- **벡터화(vectorization)**: 반복문을 NumPy 내부(C · BLAS)로 넘겨 배열 전체를 한 번에 계산하는 것
- **원소별 연산(element-wise)**: 같은 자리끼리 계산 — `x * 2`, `x ** 2`, `np.exp(x)`, `A * B`
- **행렬곱(matrix multiplication)**: C[i][j] = Σ_k A[i][k] · B[k][j]. A 의 열 수 = B 의 행 수여야 한다
- **BLAS**: C · Fortran 으로 최적화된 선형대수 라이브러리. `@` 가 내부에서 호출한다

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `A @ B` | `C = A @ B` | 행렬곱 (`np.dot(A, B)` 와 같음) |
| `np.sum()` | `A.sum(axis=0)` | 합계 (axis 로 기준 축 지정) |
| `np.mean()` | `A.mean(axis=1, keepdims=True)` | 평균 |
| `np.argmax()` | `scores.sum(axis=1).argmax()` | 최댓값의 인덱스 |

**예제 코드가 하는 일**
| 예제 | 하는 일 |
|---|---|
| 들어가며 | x × 2, x², `np.sqrt(x)`, `np.exp(x)` — 루프 없는 원소별 연산 |
| 행렬곱 for 루프 vs @ | 3중 for 루프 `matmul_loop` 를 완성해 `A @ B` 와 같은지 확인, 200×200 에서 두 방식의 시간 비교 |
| axis 를 쓰는 집계 함수 | 학생 5 × 과목 3 점수표에서 과목별 평균 **[72.6, 80.4, 78.0]**, 학생별 총점 **[240, 240, 225, 275, 175]**, 1등 = **3번** |

**핵심 내용**

#### 벡터화 — 반복을 NumPy 안으로
> 파이썬 for 루프 대신 배열 연산 한 줄로 쓰면, 실제 반복은 컴파일된 C 코드(BLAS · SIMD)가 한다
- **원소별 연산** → `x * 2`, `x ** 2`, `np.exp(x)` — 배열 전체에 한 번에
- **왜 빠른가** → 원소마다 하던 "명령 해석 · 타입 확인 · 객체 생성" 이 사라지고 연속 메모리를 한꺼번에 처리
- **속도** → 200×200 행렬곱: 3중 for 루프 대비 `@` 가 **수천 배** 빠름 (CPU 마다 다름)
- ⚠ 신경망 코드에서 원소를 파이썬 루프로 돌지 않는다 — 반복은 epoch · 배치 단위에만

#### 행렬곱 @ — 행과 열의 내적
> C[i][j] = A 의 i 행 · B 의 j 열을 원소끼리 곱해 더한 값
- **`A @ B` 의 shape 규칙** → (N, **D**) @ (**D**, H) = (N, H) — 안쪽 D 가 같아야 하고 계산 뒤 사라진다
- **`*` 와 다름** → `*` 는 같은 자리끼리 원소별 곱(shape 같아야), `@` 는 행 · 열 내적
- **신경망에서** → 한 층 계산 `X @ W` (5교시 · Day 2)
- ⚠ shape 가 같으면 `*` 도 오류 없이 돌아가 버그를 찾기 어렵다 — 행렬곱은 반드시 `@`

#### 집계와 argmax
> `np.mean` · `np.sum` · `max` 에 axis 를 주면 그 방향으로 모으고, `np.argmax` 는 최댓값의 **위치**를 돌려준다
- **예** → 성적표 (학생 5, 과목 3): `mean(axis=0)` 과목별 평균 **[72.6, 80.4, 78.0]**, `sum(axis=1)` 학생별 총점
- **argmax** → 총점 1등 학생 = **3** (값이 아니라 번호)
- **신경망에서** → 출력(클래스별 점수)의 argmax = 예측 클래스
- ⚠ 행마다 평균을 빼려면 `mean(axis=1, keepdims=True)` — 없으면 (5, 3) − (5,) 로 오류

**기본 사용형태**
```python
C = A @ B                                      # (N, D) @ (D, H) → (N, H)
scores.mean(axis=0)                            # 과목별 평균 (3,)
scores.sum(axis=1)                             # 학생별 총점 (5,)
scores.sum(axis=1).argmax()                    # 1등 학생 번호 → 3
scores - scores.mean(axis=1, keepdims=True)    # 학생별 평균을 뺀 점수
```

NumPy 배열이 있어도 파이썬 for 루프로 원소를 하나씩 계산하면 여전히 느리다. 이 교시는 루프 대신 **배열 전체를 한 번에 계산하는 벡터화**가 왜 빠른지, 그리고 신경망에서 가장 많이 쓰는 두 가지 — **행렬곱 `@`** 과 **axis 집계** — 를 본다.

#### 개념 1 · 벡터화 — 루프를 C 로 내려보낸다
`x * 2`, `x ** 2`, `np.exp(x)` 처럼 배열에 연산을 쓰면 원소마다 같은 계산이 한 번에 된다. 반복 자체는 NumPy 내부(C 코드, CPU 의 SIMD 명령)에서 일어나므로, 파이썬 루프를 도는 비용 — 2교시의 "참조 따라가기 → 타입 확인 → 새 객체" — 이 사라진다.
- 같은 200×200 행렬곱을 파이썬 3중 for 루프와 `A @ B` 로 비교하면 **수천 배** 차이가 난다 (정확한 배수는 CPU 마다 다름).
- 원칙: **신경망 코드에는 파이썬 for 루프로 원소를 돌지 않는다.** 반복은 미니배치나 epoch 처럼 큰 단위에만.

##### 🔎 왜 이렇게 되나
- **비유**: 계산을 한 명씩 손으로 시키지 않고, 계산기(C 코드 · SIMD)에 줄을 통째로 넣는 것
- **① 빠른 이유**: 반복이 NumPy 안(C)에서 일어나 파이썬 루프의 "참조 따라가기 · 타입 확인" 비용이 사라진다
- **② SIMD**: CPU 가 명령 하나로 여러 숫자를 동시에 계산
- **③ 숫자로**: 200×200 행렬곱이 3중 for 보다 수천 배 빠르다 (CPU 마다 다름)
- ⚠ 신경망 코드에 for 가 보이면 벡터화할 수 있는지부터 의심

#### 개념 2 · 행렬곱 C = A @ B
C[i][j] = Σₖ A[i][k] × B[k][j] — A 의 i 행과 B 의 j 열을 짝지어 곱해 더한 값(내적)이다.
- shape 규칙: (n, m) @ (m, p) = (n, p). **안쪽 m 이 같아야 하고**, 계산 뒤 사라진다.
- 신경망의 한 층 계산 `X @ W` 가 바로 이것이다 (5교시에서 자세히).

##### 🔎 왜 이렇게 되나
- **① C[i][j] 가 내적인 이유**: A 의 i 행과 B 의 j 열을 짝지어 곱해 더한다 — 원소마다 같은 계산
- **② 안쪽이 같아야 하는 이유**: 짝지을 원소 수가 같아야 곱해 더할 수 있다 — (n, m) @ (m, p)
- **③ 안쪽이 사라지는 이유**: 더하면서 m 개가 하나로 합쳐진다 → (n, p)
- **④ 신경망에서**: 한 층 = X @ W (5교시)
- ⚠ shape 가 같아도 `*` 는 원소별 곱 — 행렬곱은 반드시 `@`

#### 개념 3 · axis 를 쓰는 집계 — 어느 방향으로 모으나
`sum` · `mean` · `max` · `argmax` 에 axis 를 주면 그 축을 따라 모으고, 그 축은 사라진다.
- (학생 5, 과목 3) 성적표에서 `mean(axis=0)` 은 **세로로** 모아 과목별 평균 (3,), `sum(axis=1)` 은 **가로로** 모아 학생별 총점 (5,).
- `argmax` 는 최댓값의 **위치**를 돌려준다. 신경망 출력(클래스별 점수)에서 예측 클래스를 고를 때 그대로 쓴다.
- 학생별 평균을 빼려면 `mean(axis=1, keepdims=True)` (5, 1) 로 남겨야 (5, 3) 과 브로드캐스팅된다.

##### 🔎 왜 이렇게 되나
- **비유**: 성적표를 세로로 접으면 과목별, 가로로 접으면 학생별 결과
- **① axis = 없어지는 축인 이유**: 그 방향의 값들을 하나로 모으니 그 축이 사라진다 — (5, 3) 에서 axis=0 → (3,)
- **② argmax 가 위치인 이유**: 분류에서 필요한 건 가장 큰 점수의 "몇 번째 클래스인가"
- **③ keepdims=True**: 사라질 축을 크기 1 로 남겨, 원래 배열과 다시 계산(빼기 · 나누기)할 때 모양이 맞는다
- ⚠ axis 를 빼먹으면 전체를 하나로 모은다

**키워드**: `내적`, `a · b = ‖a‖‖b‖cos θ`, `노름`, `코사인 유사도`, `뉴런 = 닮음 측정기`, `선형 변환`, `회전 행렬 R(θ)`, `확대 S`, `행렬의 열 = 기준 벡터가 가는 곳`, `det`, `P @ M.T`, `X @ W + b`

**개요**: 신경망 한 층이 하는 일을 기하학으로 본다. ① **내적**은 두 벡터가 얼마나 같은 방향인가를 잰다 — 뉴런의 가중합 w · x 는 입력이 가중치 패턴과 얼마나 닮았는지 재는 것이다. ② **행렬곱은 선형 변환** — 공간을 회전 · 확대 · 찌그러뜨린다. 행렬의 각 열은 기준 벡터가 옮겨 가는 곳이다. ③ 신경망 한 층 `X (N, D) @ W (D, H) + b (H,) = Y (N, H)` 는 데이터를 새 공간으로 옮기는 변환이다.

**한눈에 보기**
선형대수 — 내적 · 선형 변환 · 한 층의 shape
> 신경망 한 층은 Y = XW + b — 입력과 가중치의 **내적**을 한꺼번에 계산하는 **행렬곱**이고, 행렬곱은 공간을 돌리고 늘리는 변환이다

- **코사인 유사도 — 길이를 빼고 방향만**: a · b / (‖a‖ ‖b‖), −1 ~ 1 — 뉴런은 입력이 가중치 패턴과 닮을수록 크게 반응

**핵심 용어**
- **내적(dot product)**: a · b = Σ aᵢbᵢ = ‖a‖‖b‖cos θ. 같은 방향이면 크고, **직각이면 0**, 반대면 음수
- **노름(norm)**: 벡터의 길이 ‖a‖ = √(a · a)
- **코사인 유사도(cosine similarity)**: (a · b) / (‖a‖‖b‖) = cos θ. 길이와 무관하게 방향만 비교 (−1 ~ 1)
- **선형 변환(linear transformation)**: 행렬곱으로 공간을 바꾸는 것. 행렬의 열 = 기준 벡터 e₁ = (1, 0), e₂ = (0, 1) 이 옮겨 가는 곳
- **행렬식(det)**: 변환 후 넓이가 몇 배가 되는지. **det = 0** 이면 평면이 직선으로 납작해져 정보가 사라진다

| `np.linalg.norm()` | `np.linalg.norm(a)` | 벡터 길이 |
| `ndarray.T` | `P @ R.T` | 전치 (행 ↔ 열) |

#### 내적 — 두 벡터가 얼마나 같은 방향인가
> a · b = Σ aᵢbᵢ = ‖a‖ ‖b‖ cos θ — 같은 방향일수록 크고, 직각이면 0, 반대면 음수
- **`np.dot` · 노름 `np.linalg.norm`** → 내적 · 벡터 길이 ‖a‖
- **코사인 유사도** → a · b / (‖a‖ ‖b‖) — 길이를 빼고 방향만 비교 (−1 ~ 1)
- **신경망에서** → 뉴런의 가중합 x · w = 입력 x 가 가중치 패턴 w 와 얼마나 닮았는지
- **예** → a = [1, 2, 2], b = [2, 0, 1] → a · b = **4**, ‖a‖ = **3**

#### 행렬곱 = 선형 변환
> 행렬을 곱하면 공간 전체가 회전 · 확대 · 찌그러지며, 행렬의 **열**은 기준 벡터 (1, 0) · (0, 1) 이 옮겨 간 위치다
- **회전 · 확대** → R(θ) = [[cos θ, −sin θ], [sin θ, cos θ]], S = [[sx, 0], [0, sy]]
- **합성** → `S @ R` = 먼저 R(회전), 다음 S(확대) — 오른쪽 행렬이 먼저 적용
- **점을 행으로 쌓으면** → P (N, 2) 의 변환은 `P @ M.T` (`ndarray.T` = 행 ↔ 열 전치)
- **예** → (1, 0) 을 90° 회전하면 **(0, 1)**
- ⚠ 행렬식(det) = 0 이면 평면이 직선으로 납작해져 되돌릴 수 없다

#### 신경망 한 층의 shape — Y = XW + b
> X (N, D) @ W (D, H) + b (H,) = Y (N, H) — 행 = 샘플, 열 = 특징
- **N · D · H** → 샘플(배치) 수 · 입력 특징 수 · 출력(뉴런) 수
- **b** → 브로드캐스팅으로 모든 행(샘플)에 더해진다
- **예** → 샘플 4개 · 특징 3개 → 출력 2개: W **(3, 2)**, b **(2,)**, Y **(4, 2)**
- ⚠ 1차원 (3,) 끼리 `@` 는 스칼라(내적) — 행렬이 필요하면 `reshape(1, 3)`

**기본 사용형태**

(a @ b) / (np.linalg.norm(a) * np.linalg.norm(b))   # 코사인 유사도

#### 개념 2 · 행렬곱 = 선형 변환
점(벡터)에 행렬을 곱하면 공간이 돌거나(회전) 늘어나는(스케일) 변환이 된다.

### 6교시 · 미분과 기울기

**키워드**: `순간 변화율`, `할선 → 접선`, `중앙 차분`, `h = 1e-4`, `반올림 오차`, `편미분`, `기울기(gradient) ∇f`, `가장 가파른 오르막`, `−∇f`, `numerical_gradient`, `되돌리기`, `gradient check`

**개요**: 학습의 고리에서 "어느 쪽으로 바꾸면 손실이 줄어드나" 를 알려 주는 것이 미분이다. ① 미분 = h → 0 의 순간 변화율, 컴퓨터에서는 **중앙 차분** (f(x+h) − f(x−h)) / 2h 로 근사하고 **h ≈ 1e-4** 를 쓴다. ② 변수가 여러 개면 하나씩만 움직이는 **편미분**을 모은 벡터가 **기울기 ∇f** — 함수값이 가장 빨리 커지는 방향이고, 그 반대(−∇f)로 가면 가장 빨리 작아진다(경사하강의 원리). ③ 임의 shape 배열의 기울기를 구하는 `numerical_gradient` 는 Day 3 역전파 검증의 정답지가 된다.

**한눈에 보기**
미분과 기울기 — 어느 쪽으로 움직여야 손실이 줄까
> 기울기 ∇f 는 편미분을 모은 벡터로, 함수값이 **가장 빨리 커지는 방향**을 가리킨다 — 학습은 그 반대(−∇f)로 파라미터를 옮긴다
- **미분 = 아주 조금 움직였을 때의 변화율**: (x²)′ = 2x → x = 3 에서 6
- **수치 미분은 중앙 차분으로**: (f(x + h) − f(x − h)) / 2h — 한쪽 차분보다 훨씬 정확 (오차 ∝ h²)
- **h 는 1e-4 가 적당 — 너무 작으면 반올림 오차**: x² 의 x = 3 에서 h = 1e-12 → 오차 5×10⁻⁴, 1e-15 → 0.67
- **numerical_gradient — 원소를 하나씩 ±h 흔들기**: f = x₀² + x₁² 의 (3, 4) 에서 ∇f = (6, 8) · 원소 하나당 f 2번이라 느리다 → Day 3 역전파
- **⚠ 흔든 원소를 원래 값으로 되돌리지 않으면 다음 기울기가 틀린다**: `x[idx] = orig` · 정수 배열이면 기울기 0

**핵심 용어**
- **미분(derivative)**: 순간 변화율 f'(x) = lim (f(x+h) − f(x)) / h. 그래프에서는 그 점의 **접선의 기울기**
- **수치 미분(numerical differentiation)**: 아주 작은 h 로 미분을 근사 — 중앙 차분이 오차가 작다
- **중앙 차분(central difference)**: (f(x+h) − f(x−h)) / 2h. 근사 오차가 **h²** 에 비례
- **편미분(partial derivative)**: 변수 하나만 움직이고 나머지는 고정한 미분
- **기울기(gradient, ∇f)**: 편미분을 모은 벡터. 함수값이 **가장 빨리 커지는 방향**. 등고선에 수직

**이 교시에서 만드는 함수**

|---|---|---|
| `numerical_diff()` | `numerical_diff(f, x, h=1e-4)` | 중앙 차분으로 f'(x) 근사 |
| `numerical_gradient()` | `numerical_gradient(f, x, h=1e-4)` | 임의 shape 배열 x 에 대한 기울기 — Day 3 gradient check 의 정답지 |

**핵심 내용**

#### 미분 — 아주 조금 움직였을 때의 변화율
> f′(x) = lim(h → 0) (f(x + h) − f(x)) / h — 그 점에서 접선의 기울기
- **신경망에서** → "파라미터를 아주 조금 바꾸면 손실이 얼마나 바뀌나"
- **할선 → 접선** → 두 점 사이 평균 변화율에서 h 를 0 으로 줄인 극한
- **예** → (x²)′ = 2x → x = 3 에서 **6**

#### 수치 미분 — 중앙 차분과 h
> 컴퓨터는 극한을 못 하므로 작은 h 로 근사: f′(x) ≈ (f(x + h) − f(x − h)) / 2h
- **`numerical_diff` (중앙 차분)** → 양쪽을 봐서 한쪽 차분 (f(x+h) − f(x)) / h 보다 훨씬 정확 (오차 ∝ h²)
- **h = 1e-4** → 적당한 값 — 너무 작으면 반올림 오차 (x² 의 x = 3 에서 h = 1e-12 → 오차 **5×10⁻⁴**, 1e-15 → **0.67**)
- **float32** → `np.float32(1e-50)` = **0.0** — 작은 수가 아예 사라진다
- ⚠ "h 는 작을수록 정확" 은 틀림 → **1e-4**

#### 기울기(gradient) — 가장 가파른 오르막
> 편미분을 모은 벡터 ∇f = (∂f/∂x₀, ∂f/∂x₁, …) — 함수값이 가장 빨리 커지는 방향을 가리킨다
- **편미분** → 한 변수만 움직이고 나머지는 고정해서 미분
- **−∇f** → 가장 가파른 내리막 → 경사하강은 이 방향으로 (8교시)
- **예** → f = x₀² + x₁² 의 (3, 4) 에서 ∇f = **(6, 8)**
- ⚠ 기울기 방향으로 **더하면** 손실이 커진다 — 경사하강은 **빼기**

#### numerical_gradient — 원소마다 흔들어 보기
> 배열의 원소를 하나씩 ±h 로 움직여 f 를 두 번 계산하고, 끝나면 **원래 값으로 되돌린다**
- **어떤 shape 든** → `np.nditer(x, flags=["multi_index"])` 로 모든 칸 순회
- **비용** → 원소 하나당 f 를 2번 → 파라미터가 많으면 매우 느림 (Day 3 역전파가 필요한 이유)
- **쓰임** → 느리지만 거의 확실 → 공식으로 구한 기울기의 **정답지** (gradient check)
- ⚠ 되돌리기(`x[idx] = orig`)를 빠뜨리면 다음 원소의 기울기가 틀린다 · 정수 배열이면 기울기 0

**기본 사용형태**
```python
def numerical_diff(f, x, h=1e-4):
    return (f(x + h) - f(x - h)) / (2 * h)

def numerical_gradient(f, x, h=1e-4):
    grad = np.zeros_like(x)
    it = np.nditer(x, flags=["multi_index"])
    while not it.finished:
        idx = it.multi_index
        orig = x[idx]
        x[idx] = orig + h; fxh1 = f(x)
        x[idx] = orig - h; fxh2 = f(x)
        grad[idx] = (fxh1 - fxh2) / (2 * h)
        x[idx] = orig                       # 되돌리기!
        it.iternext()
    return grad
```

### 7교시 · 확률 기초

**개요**: 신경망은 **난수로 가중치를 초기화**하고(Day 4) **확률로 답을 낸다**(Day 2 Softmax). ① 평균 · 분산 · 표준편차와 두 분포(평평한 **균등**, 종 모양 **정규**)를 NumPy 로 뽑아 보고, ② seed 로 결과를 **재현**하며, ③ **표준화**로 평균 0 · 표준편차 1 을 만든다. ④ Day 2 손실 함수에서 마주칠 **log(0) = −inf** 와 **exp overflow** 를 미리 본다.

**한눈에 보기**
확률 기초 — 분포 · 표준화 · log
> 가중치를 처음 정하는 **난수 분포**, 특징의 크기를 맞추는 **표준화**, 확률을 벌점으로 바꾸는 **−log** — Day 2 ~ 4 의 손실 · 초기화 · BatchNorm 의 바탕
- **정규분포는 평균 ± 1σ 안에 68%, ± 2σ 안에 95%**: `rng.normal(μ, σ, n)` · 균등은 `rng.uniform(a, b, n)` — Day 4 Xavier · He 초기화
- **표준화 = (x − 평균) / 표준편차**: 단위가 다른 특징을 "평균 0, 표준편차 1" 로 맞춰 고르게 학습 — z = 1.5 면 평균보다 1.5σ 위
- **−log p — 확신하며 틀릴수록 큰 벌점**: p = 1 이면 0, p → 0 이면 무한히 커진다 (Day 2 교차 엔트로피)
- **⚠ `np.log(0)` = −∞, `np.exp(1000)` = inf**: 확률에 1e-7 을 더하고 (log(1e-7) ≈ −16.1), softmax 는 최댓값을 뺀다
- **⚠ `x.std()` 는 N 으로 나눈다**: 표본 표준편차(N − 1)는 `ddof=1` · seed 를 고정해야 실험을 비교할 수 있다

**핵심 용어**
- **평균(mean, μ)**: (1/N) Σ xᵢ — `x.mean()`
- **분산(variance, σ²)**: (1/N) Σ (xᵢ − μ)² — 평균에서 얼마나 퍼졌나. `x.var()`
- **표준편차(standard deviation, σ)**: 분산의 제곱근 — `x.std()`
- **균등분포(uniform) U(a, b)**: 구간 안 모든 값이 같은 확률 — 평평한 히스토그램 (Xavier uniform 초기화)
- **정규분포(normal) N(μ, σ²)**: 평균 근처가 가장 많은 종 모양. ±1σ 약 **68%**, ±2σ 약 **95%** (He normal 초기화)
- **표준화(standardization)**: (x − μ) / σ → 평균 **0**, 표준편차 **1** (입력 정규화 · BatchNorm 의 기초)
- **seed**: 난수 생성의 출발점. 같은 seed → 같은 난수열

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `rng.uniform()` | `rng.uniform(-1, 1, 10_000)` | 균등분포 난수 |
| `rng.normal()` | `rng.normal(0, 1, 10_000)` | 정규분포 난수 |
| `np.std()` | `x.std()` · `x.std(ddof=1)` | 표준편차 (모집단 N · 표본 N−1) |
| `np.log()` | `np.log(p + 1e-7)` | 자연로그 — 확률 → 손실 |
| `np.exp()` | `np.exp(x)` | 지수 — 점수 → 확률 |

#### 확률 분포 — 균등과 정규
> 균등분포는 구간 안 모든 값이 같은 확률(평평), 정규분포는 평균 근처가 많고 멀수록 드문 종 모양
- **정규분포의 성질** → 평균 ± 1σ 안에 **68%**, ± 2σ 안에 **95%**
- **함수** → `rng.uniform(a, b, n)` · `rng.normal(μ, σ, n)` · `rng.integers(1, 7, n)` (끝값 미포함)
- **신경망에서** → 가중치 초기값 (Day 4 Xavier · He)
- ⚠ seed 를 고정해야(`default_rng(42)`) 실행마다 같은 난수 → 실험 비교 가능

#### 표준화
> (x − 평균) / 표준편차 — 단위 · 크기가 다른 값을 "평균 0, 표준편차 1" 눈금으로 맞추는 변환
- **왜** → 크기가 다른 특징(키 cm · 몸무게 kg)이 학습에 고르게 기여하게 하려고
- **z 값의 뜻** → 평균에서 표준편차 몇 개만큼 떨어졌나 (z = 1.5 → 평균보다 1.5σ 위)
- **신경망에서** → 입력 정규화 · Day 4 BatchNorm (층마다 표준화)
- ⚠ `np.std` (= `x.std()`) 는 분산을 N 으로 나눠 제곱근 — 표본 표준편차(N − 1)는 `ddof=1`

#### log 와 exp — 확률을 손실로, 점수를 확률로
> −log p 는 정답에 준 확률 p 를 벌점으로 바꾸고, exp 는 점수를 양수로 바꿔 확률을 만든다 (Day 2 손실 · softmax)
- **−log p** → p = 1 이면 0, p 가 0 에 가까울수록 무한히 커진다 — 확신하며 틀릴수록 큰 벌점
- **`np.log(0)` = −∞** → 이후 계산이 모두 nan → 확률에 **1e-7** 을 더한다 (log(1e-7) ≈ **−16.1**)
- **exp overflow** → `np.exp(1000)` = inf → Day 2 softmax 에서 최댓값을 빼서 해결

### 8교시 · 미니 프로젝트: 경사하강법으로 최소점 찾기

**키워드**: `경사하강`, `p ← p − η∇f(p)`, `f = x² + 3y²`, `∇f = (2x, 6y)`, `학습률 η`, `수렴 · 진동 · 발산`, `y ← (1 − 6η) y`, `0 < η < 1/3`, `history (steps + 1, 2)`, `노름 > 1e6`

**개요**: 1~7교시 도구로 학습의 고리를 처음 돌린다. ① 목표 함수 f(x, y) = x² + 3y² 의 최소점 (0, 0) 을 **경사하강** p ← p − η∇f(p) 로 찾는다. ② 해석적 기울기를 6교시의 `numerical_gradient` 와 비교해 맞는지 검증한다. ③ 학습률을 0.01 · 0.1 · 0.3 · 0.35 로 바꿔 경로를 비교하면 — 작으면 느리고, 적당하면 수렴, 크면 진동 · 발산한다. 가장 가파른 방향(y)이 학습률의 상한을 정한다.

**한눈에 보기**
경사하강법 — 기울기 반대로 조금씩 내려가기
> p ← p − η∇f(p) — 기울기의 반대 방향으로 학습률 η 만큼 걷기를 반복해 최소점을 찾는 방법 (신경망 학습의 원형)
- **기울기 공식을 수치 미분과 비교해 검증한다**: 최대 오차 < 1e-6 이면 통과 (이 함수는 약 1.6×10⁻¹¹) — Day 3 역전파 검증의 축소판
- **한 걸음 예**: f = x² + 3y², ∇f = (2x, 6y) · (−4, 2) 에서 η = 0.1 → (−3.2, 0.8)
- **학습률은 가장 가파른 방향이 상한을 정한다**: y ← (1 − 6η)y 라서 |1 − 6η| < 1 → 0 < η < 1/3
- **⚠ 위치를 제자리에서 바꾸며 기록하면 기록이 전부 같아진다**: `history.append(p.copy())` · 손실이 nan 이면 학습률부터 의심

**핵심 용어**
- **경사하강법(gradient descent)**: p ← p − η∇f(p) 를 반복해 함수의 최소점을 찾는 방법
- **학습률(learning rate, η)**: 한 번에 기울기 반대 방향으로 이동하는 크기
- **해석적 기울기(analytic gradient)**: 미분 공식으로 직접 구한 기울기 — 여기서는 (2x, 6y). 빠르고 정확
- **발산(divergence)**: 갱신할수록 값이 커져 최소점에서 멀어지는 것

**이 교시에서 만드는 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `gradient_descent()` | `gradient_descent(grad, init, lr, steps)` | init 에서 steps 번 갱신, 출발점 포함 경로 (steps+1, 2) 반환. 노름 > 1e6 이면 발산으로 멈춤 |

**핵심 내용**

#### 경사하강법
> p ← p − η ∇f(p) — 기울기의 반대 방향으로 학습률 η 만큼 이동하는 걸음을 반복해 최소점을 찾는다
- **학습률(η)** → 한 걸음의 크기
- **`gradient_descent()`** → 걸음을 steps 번 반복하며 위치를 history 에 모은다 → shape (steps + 1, 2)
- **예** → f = x² + 3y², ∇f = (2x, 6y), (−4, 2) 에서 η = 0.1 → 한 걸음 뒤 **(−3.2, 0.8)**
- ⚠ 위치를 제자리에서 바꾸며 `history.append(p)` 하면 기록이 모두 같은 배열 → **`p.copy()`**

#### 해석 기울기 검증 (gradient check)
> 손으로 미분한 공식(해석 기울기)을 수치 미분과 비교해 맞는지 확인한다 — Day 3 역전파 검증의 축소판
- **해석 기울기** → 빠르고 정확하지만 공식이 틀릴 수 있다
- **수치 기울기** → 느리지만 거의 확실 → 정답지
- **기준** → 최대 오차 < **1e-6** 이면 통과 (이 함수는 약 **1.6×10⁻¹¹**)

#### 학습률과 수렴
> 매 걸음 x ← (1 − 2η)x, y ← (1 − 6η)y — 곱하는 수의 **절댓값이 1 보다 작아야** 수렴한다
| η | y 에 곱하는 수 | 30걸음 결과 |
|---|---|---|
| 0.01 | 0.94 | 느림 — f ≈ **5.05** |
| 0.1 | 0.4 | 수렴 — f ≈ **2.5×10⁻⁵** |
| 0.3 | −0.8 | 지그재그로 수렴 |
| 0.35 | −1.1 | **발산** (y ≈ **34.9**) |
- **수렴 조건** → |1 − 6η| < 1 → **0 < η < 1/3** — 가장 가파른 방향(y)이 상한을 정한다
- **신경망에서** → 방향마다 경사가 크게 다르다 → Day 4 Momentum · Adam
- ⚠ 손실이 nan 이 되면 학습률부터 의심 (너무 크면 발산)

**기본 사용형태**
```python
f      = lambda p: p[0] ** 2 + 3 * p[1] ** 2
grad_f = lambda p: np.array([2 * p[0], 6 * p[1]])

def gradient_descent(grad, init, lr, steps):
    p = np.array(init, dtype=float)
    history = [p.copy()]
    for _ in range(steps):
        p = p - lr * grad(p)
        history.append(p.copy())
        if np.linalg.norm(p) > 1e6:          # 발산
            break
    return np.array(history)

h = gradient_descent(grad_f, [-4.0, 2.0], lr=0.1, steps=100)   # h[-1] ≈ (0, 0)
```

**상세 학습**

#### 이 교시에서 답하는 질문
오늘 만든 도구로 **학습의 고리 중 "기울기 → 갱신"** 을 처음 직접 돌린다. 함수의 최소점을 **경사하강법**으로 찾고, 학습률이 결과를 어떻게 바꾸는지 — 너무 작으면 느리고, 너무 크면 튀거나 발산하는 이유 — 를 본다.

#### 개념 1 · 경사하강법 — 기울기 반대 방향으로 조금씩
> p ← p − η · ∇f(p)

- 6교시: ∇f 는 가장 가파른 오르막. 그 반대로 아주 조금(학습률 η 만큼) 이동하면 f 가 줄어든다. 이것을 반복하면 최소점에 다가간다.
- 목표 함수 f(x, y) = x² + 3y², 기울기 ∇f = (2x, 6y) — 손으로 미분한 식(해석적 기울기)을 numerical_gradient 와 비교해 확인한다 (최대 오차 약 1.6 × 10⁻¹¹).
- (−4, 2) 에서 학습률 0.1 로 한 번 이동하면 p₁ = (−4, 2) − 0.1 × (−8, 12) = **(−3.2, 0.8)**. 100번이면 거의 (0, 0).

##### 🔎 왜 이렇게 되나
- **비유**: 안개 낀 산에서 발밑 경사가 가장 가파르게 내려가는 쪽으로 한 걸음씩
- **① −η∇f 인 이유**: −∇f 가 가장 가파른 내리막, η 는 한 걸음 크기
- **② 반복하는 이유**: 기울기는 지금 자리 기준이라 한 번에 최소점으로 갈 수 없다 — 조금 가고 다시 잰다
- **③ 손으로 구한 기울기와 비교하는 이유**: 식이 맞는지 수치 미분으로 확인 — Day 3 gradient check 의 축소판
- ⚠ 위치를 기록할 때 `p.copy()` — 제자리에서 바뀌는 배열을 그대로 넣으면 기록이 모두 같아진다

#### 개념 2 · 학습률 — 너무 작으면 느리고, 너무 크면 튄다
![x² + 3y² 위의 경사하강 경로 — 학습률 0.1 은 부드럽게, 0.3 은 y 방향으로 지그재그](assets/fig/nn/d1-gd-paths.svg)

| 학습률 | 30 step 후 f | 일어나는 일 |
|---|---|---|
| 0.01 | 약 5.05 | 너무 작아 아직 멀었다 (느림) |
| 0.1 | 약 2.5 × 10⁻⁵ | 부드럽게 수렴 |
| 0.3 | 약 1.8 × 10⁻⁵ | y 방향으로 부호를 바꾸며 지그재그, 그래도 수렴 |
| 0.35 | 약 3,654 | y 가 커지며 **발산** |

- **왜 그런가**: 이 함수는 y 방향이 x 방향보다 3배 가파르다. 매 step y 는 (1 − 6η) 배가 되는데, |1 − 6η| < 1 이어야 줄어든다 → **0 < η < 1/3**. 가장 가파른 방향이 학습률의 **상한**을 정하고, 그 학습률로는 완만한 x 방향이 느리다.
- 실제 신경망의 손실 지형도 방향마다 경사가 크게 다르다 → Day 4 의 Momentum · Adam 이 이 문제를 다룬다.

##### 🔎 왜 이렇게 되나
- **비유**: 보폭 — 너무 작으면 해가 지도록 못 가고, 너무 크면 골짜기를 건너뛰어 반대편 벽으로 튄다
- **① 상한이 있는 이유**: 가장 가파른 방향(y, 6y)에서 y ← (1 − 6η)y — |1 − 6η| < 1 이어야 줄어든다 → η < 1/3
- **② 0.3 이 지그재그인 이유**: 1 − 6 · 0.3 = −0.8 — 부호가 바뀌며 줄어든다
- **③ 0.35 가 발산하는 이유**: 1 − 6 · 0.35 = −1.1 — 매번 더 커진다
- ⚠ 손실이 nan 이 되면 학습률부터 의심

#### 한 번에 정리
- 경사하강 = 기울기 반대 방향으로 학습률만큼 이동, 반복.
- 학습률: 너무 작으면 느림, 너무 크면 지그재그 · 발산. 가장 가파른 방향이 상한을 정한다 (x² + 3y² 는 1/3).
- 오늘 고리의 "기울기 → 갱신" 을 돌렸다 → Day 2 에서 모델 · 손실을 붙여 데이터로 학습한다.
- ⚠ `history.append(p)` 만 하고 `p.copy()` 를 빠뜨리면, p 를 제자리에서 바꿀 때 기록이 모두 같은 배열이 된다.
