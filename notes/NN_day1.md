**핵심 내용**

#### AI ⊃ 머신러닝 ⊃ 딥러닝
> 가장 넓은 말이 AI, 그중 "데이터에서 규칙을 찾는" 것이 머신러닝, 그중 "층을 깊게 쌓은 신경망"이 딥러닝
- **AI** → 규칙을 사람이 짜도 AI (체스 프로그램)
- **머신러닝** → 규칙을 **데이터에서** 찾는다
- **딥러닝** → 층이 깊을수록 이미지 · 음성처럼 **말로 규칙을 쓰기 어려운** 문제를 푼다
- **이 과정의 모델** → YOLO · 센서 이상 감지 모두 가장 안쪽 원(딥러닝)

#### 규칙을 쓰는가, 데이터에서 찾는가
> 머신러닝은 입력 · 정답 쌍을 주고 컴퓨터가 규칙의 **숫자**를 찾게 하는 것
- **전통 프로그래밍** → 규칙 `F = 1.8C + 32` 를 사람이 코드로 쓴다
- **머신러닝** → (섭씨, 화씨) 쌍을 잔뜩 주면 컴퓨터가 **w = 1.8, b = 32** 를 찾는다
- **"헬멧을 썼는가?"** → 말로 쓸 수 없는 규칙 → 머신러닝이 필요한 문제
- **파라미터 개수** → 화씨 예제 **2개** · Day 3 MNIST 신경망 **약 8만 개** · YOLOv8n **약 300만 개**

#### 학습 = 최적화
> θ* = argmin_θ L(θ) — 손실 L 을 가장 작게 만드는 파라미터 θ 를 찾는 일
- **argmin** → "함수값이 최소가 되는 **입력**" (최솟값 자체가 아니라 그 위치)
- **학습이 끝났다** → 손실이 더 이상 줄지 않는 θ 를 찾았다
- **5일 계획** → Day 1 도구(NumPy · 미분 · 경사하강) · Day 2 뉴런 · 순전파 · 손실 · Day 3 역전파 → MNIST · Day 4 옵티마이저 · 초기화 · BatchNorm · Dropout → `mynn.py` · Day 5 합성곱 · 풀링 → CNN

#### 학습의 고리 — 5일의 지도
> 모델로 예측 → 손실로 채점 → 기울기로 방향 찾기 → 갱신으로 조금 이동 → 반복
| 단계 | 하는 일 | 만드는 날 |
|---|---|---|
| 모델 y = f(x; θ) | 입력에 파라미터를 곱하고 더해 예측 | Day 2 순전파 |
| 손실 L | 예측과 정답의 차이를 숫자 하나로 | Day 2 MSE · Cross-Entropy |
| 기울기 ∂L/∂θ | 파라미터를 어느 쪽으로 바꾸면 손실이 줄어드나 | Day 1 미분 · Day 3 역전파 |
| 갱신 θ ← θ − η∇L | 기울기 **반대** 방향으로 조금 이동 | Day 1 경사하강 · Day 4 옵티마이저 |

##### 자세히

#### 개념 3 · 학습 = 최적화, 그리고 학습의 고리

### 2교시 · Python 속성 (C 개발자용)

**키워드**: `변수 = 이름표`, `동적 타입`, `is vs ==`, `id()`, `가변 · 불변`, `b = a 는 공유`, `.copy()`, `참조의 배열`, `/ 와 //`, `a[-1]`, `리스트 컴프리헨션`

**개요**: C 개발자가 Python 에서 가장 많이 틀리는 지점은 **"변수 = 메모리 칸"** 이라는 생각이다. ① Python 의 변수는 heap 의 객체에 붙인 **이름표**이고 타입은 객체에 붙어 있다(동적 타입). ② 그래서 `b = a` 는 복사가 아니라 이름표를 하나 더 붙이는 것 — 리스트 · ndarray 같은 **가변 객체**는 한쪽을 바꾸면 다른 쪽에도 보인다. ③ 리스트의 칸에는 값이 아니라 **참조**가 들어 있어 숫자 계산이 느리다 → 3교시 NumPy 가 필요한 이유.

**핵심 용어**
- **이름(name)**: 객체를 가리키는 이름표. `a = 3` 은 int 객체 3 에 a 라는 이름표를 붙이는 것
- **동적 타입(dynamic typing)**: 타입이 변수가 아니라 **객체**에 붙어 있어, 같은 이름이 다른 타입 객체를 가리킬 수 있음
- **가변 객체(mutable)**: 제자리에서 바뀌는 객체 — list · dict · **ndarray**. `b = a` 로 공유된다
- **불변 객체(immutable)**: 바뀌지 않는 객체 — int · float · str · tuple. `y = y + 1` 은 **새 객체**를 만들어 이름표를 옮긴다
- **참조(reference)**: 객체를 가리키는 값. 리스트의 칸에는 값 대신 참조가 들어 있다

**예제 코드가 하는 일**
| 예제 | 하는 일 |
|---|---|
| C 의 변수 vs Python 의 이름 | `b = a` · `c = a.copy()` 를 만들고 `is` · `==` · `id` 로 같은 객체인지, 같은 값인지 비교 |
| C 배열 vs Python 리스트 | 동적 타입(`type(x)` 가 바뀜), 2¹⁰⁰ 도 정확, 리스트 · 딕셔너리 · 함수 · 클래스 기본 문법 |
| C → Python 바꿔 쓰기 | `sum(range(1, 101))` = **5050**, 컴프리헨션으로 짝수 제곱 `[0, 4, 16, 36, 64]` |

**핵심 내용**

#### 변수 = 객체에 붙인 이름표
> C 의 `int a = 3;` 은 값이 든 메모리 칸, Python 의 `a = 3` 은 heap 의 int 객체에 붙인 이름표
- **`b = a`** → 값 복사가 아니라 **같은 객체에 이름표 하나 더**
- **타입** → 객체에 붙어 있다 — `x = 3` → `x = "three"` 가 오류 없이 됨 (동적 타입)
- **정수** → 크기 제한이 없다 — `2 ** 100` 도 정확 (C 의 overflow 없음)

#### 같은 객체인가(is) vs 같은 값인가(==)
> `is` = 같은 객체(id 가 같다), `==` = 값이 같다
- **`b = a`** → `a is b` **True**, `id(a) == id(b)` True
- **`c = a.copy()`** → `a is c` **False**, `a == c` True — 값만 같은 별개 객체
- **가변(list)** → `b.append(4)` 하면 `a` 도 `[1, 2, 3, 4]`
- **불변(int)** → `y = x; y = y + 1` 은 새 객체 4 를 만들어 y 만 옮김 → x 는 그대로 3
- ⚠ `b = a` 를 복사로 착각 → 리스트 · ndarray 는 **`.copy()`** (Day 3 역전파에서 `W.copy()` 를 빼먹으면 원본 가중치가 바뀌는 버그)
##### 자세히
| 구분 | 예 | `b = a` 후 b 를 바꾸면 |
|---|---|---|
| 불변 (immutable) | int, float, str, tuple | a 는 그대로 (b 가 새 객체로 옮겨 감) |
| 가변 (mutable) | list, dict, ndarray | **a 도 바뀜** (같은 객체) |

#### 리스트는 참조의 배열 — 왜 NumPy 가 필요한가
> 리스트 칸에는 값이 아니라 객체를 가리키는 참조가 들어 있다 → 유연하지만 숫자 계산이 느리다
- **장점** → 길이가 자유롭고 타입이 섞여도 됨 (`[3, "a", 2.0]`)
- **숫자 하나 더할 때마다** → 참조 따라가기 → 타입 확인 → 덧셈 → 새 객체 만들기
- **해결** → NumPy ndarray 는 C 배열처럼 **값을 연속으로** 저장 (3교시)

#### C 와 다른 문법 — 자주 틀리는 것
> 들여쓰기가 문법이고, 나눗셈 · 인덱스 규칙이 C 와 다르다
- **`for i in range(n):`** → C 의 `for (i=0; i<n; i++)` (반복 가능한 객체를 순회)
- **`class` · `self`** → `struct` + 메서드, `self` = C 의 this 포인터
- **`a, b = b, a`** → 임시 변수 없이 맞바꾸기
- **`[x ** 2 for x in range(10) if x % 2 == 0]`** → 리스트 컴프리헨션 → `[0, 4, 16, 36, 64]`
- ⚠ **`7 / 2` = 3.5** (항상 실수) · 정수 몫은 **`7 // 2` = 3**
- ⚠ `a[-1]` 은 **마지막 원소** (오류 아님)
- ⚠ 탭과 스페이스를 섞으면 `IndentationError`

**기본 사용형태**
```python
a = [1, 2, 3]
b = a            # 같은 객체 (a is b → True)
c = a.copy()     # 독립 사본 (a is c → False, a == c → True)
b.append(4)      # a 도 [1, 2, 3, 4]

total = sum(range(1, 101))                         # 5050
squares = [x ** 2 for x in range(10) if x % 2 == 0]
counts = {}
for w in "cat dog cat".split():
    counts[w] = counts.get(w, 0) + 1               # {'cat': 2, 'dog': 1}
```

#### 이 교시에서 답하는 질문
C 를 배운 사람이 Python 에서 가장 많이 틀리는 지점은 "변수 = 메모리 칸" 이라는 생각이다. 이 교시는 Python 의 변수가 실제로 무엇인지, 그것이 왜 **복사 버그**를 만드는지, 그리고 왜 숫자 계산에는 리스트 대신 **NumPy** 가 필요한지 본다.

#### 개념 1 · 변수는 메모리 칸이 아니라 객체에 붙인 이름표
- **C**: `int a = 3;` 은 값 3 이 든 메모리 칸 a 를 만든다. `b = a` 는 값을 다른 칸에 **복사**한다.
- **Python**: `a = 3` 은 heap 어딘가의 int 객체 3 에 **이름표 a 를 붙이는 것**이다. `b = a` 는 같은 객체에 이름표 b 를 **하나 더** 붙인다 — 복사가 아니다.
- 타입도 변수가 아니라 객체에 붙어 있다(동적 타입). 그래서 `x = 3` 다음에 `x = "three"` 가 오류 없이 된다.

![C 는 변수 = 값이 든 칸, Python 은 변수 = 객체를 가리키는 이름표](assets/fig/nn/d1-variables.svg)

#### 개념 2 · 가변 객체는 공유된다 — is 와 ==
- `is` 는 **같은 객체**인가(id 가 같은가), `==` 는 **값이 같은가** 를 묻는다.
- **가변(mutable) 객체** — list, dict, NumPy 배열 — 는 제자리에서 바뀐다. `b = a` 로 공유한 뒤 `b.append(4)` 하면 a 도 `[1, 2, 3, 4]` 가 된다.
- **불변(immutable) 객체** — int, float, str, tuple — 는 바뀌지 않는다. `y = y + 1` 은 새 객체를 만들어 y 이름표만 옮기므로 x 는 그대로다.
- 진짜 복사본이 필요하면 **`.copy()`**. 이 규칙은 NumPy 배열에도 그대로라, Day 3 에서 `W.copy()` 를 빠뜨리면 원본 가중치가 바뀌는 버그가 생긴다.

| 구분 | 예 | `b = a` 후 b 를 바꾸면 |
|---|---|---|
| 불변 | int, float, str, tuple | a 는 그대로 (b 만 새 객체로) |
| 가변 | list, dict, ndarray | **a 도 바뀐다** (같은 객체) |

#### 개념 3 · 리스트는 참조의 배열 — 그래서 NumPy 가 필요하다
- C 배열은 값이 메모리에 연속으로 놓인다. Python 리스트의 칸에는 값이 아니라 **객체를 가리키는 참조**가 들어 있고, 객체들은 heap 여기저기에 흩어져 있다.
- 장점은 유연함(길이 자유, 타입 섞기 가능)이지만, 숫자 하나를 더할 때마다 "참조 따라가기 → 타입 확인 → 덧셈 → 새 객체 만들기" 를 반복하니 **숫자 계산이 느리다**.
- 신경망은 수만 ~ 수백만 개의 숫자를 계산한다 → 값을 연속 메모리에 담는 NumPy 배열(3교시)이 필요한 이유.

#### 코드로 확인
```python
a = [1, 2, 3]
b = a            # 같은 객체에 이름표 하나 더
c = a.copy()     # 값만 같은 새 객체
print(a is b, a is c, a == c)
```
- **무엇을 하나**: 같은 리스트를 공유하는 b 와 복사본 c 를 만들고, 같은 객체인지 · 같은 값인지 비교한다.
- **어떤 개념**: 개념 1 · 2 — 이름표, is vs ==.
- **출력**: `True False True`

```python
x = 3
y = x
y = y + 1        # int 는 불변 → 새 객체 4 를 만들어 y 를 옮긴다
print(x, y)
```
- **무엇을 하나**: 불변 객체를 공유한 뒤 한쪽을 "바꾼다".
- **어떤 개념**: 개념 2 — 불변 객체는 새 객체가 생긴다.
- **출력**: `3 4`

```python
squares = [x ** 2 for x in range(10) if x % 2 == 0]
```
- **무엇을 하나**: 0~9 중 짝수의 제곱을 한 줄로 모은다 (리스트 컴프리헨션).
- **어떤 개념**: C 의 for 루프를 Python 답게 바꿔 쓰기.
- **출력**: `[0, 4, 16, 36, 64]`

#### 한 번에 정리
- Python 변수 = 객체에 붙인 이름표. `b = a` 는 복사가 아니다.
- 가변 객체(list · ndarray)는 공유되므로 복사가 필요하면 `.copy()`.
- 리스트 = 참조의 배열 → 유연하지만 숫자 계산이 느리다 → NumPy.

### 3교시 · NumPy ndarray

**키워드**: `ndarray`, `ndim · shape · size · dtype`, `strides (32, 8)`, `view vs copy`, `np.shares_memory`, `불리언 마스크`, `axis = 없어지는 축`, `keepdims`, `브로드캐스팅`, `오른쪽 축부터`, `(3,) vs (3, 1)`

**개요**: 신경망의 입력 · 가중치 · 출력은 전부 **ndarray** 다. ① ndarray 는 같은 dtype 숫자를 메모리에 **한 줄로** 놓고, shape · strides 라는 "읽는 규칙"으로 다차원처럼 보여 준다 — 그래서 reshape · 슬라이스는 복사 없이 **view** 를 만든다. ② 집계 함수의 **axis 는 "없어지는 축"** 이다. ③ **브로드캐스팅**은 shape 를 오른쪽 끝부터 맞춰 크기 1 인 축을 늘리는 규칙 — 신경망 한 층의 `X @ W + b` 에서 편향이 모든 샘플에 더해지는 원리다.

**핵심 용어**
- **ndarray**: NumPy 다차원 배열. 같은 dtype 의 값이 **연속 메모리**에 놓여 있다 (C 의 `double a[3][4]` 와 같은 구조)
- **shape**: 각 축의 크기 튜플 — `np.zeros((3, 4))` 는 `(3, 4)`, ndim **2**, size **12**
- **dtype**: 원소 타입 — 정수 리스트는 `int64`, 실수는 `float64`
- **strides**: 각 축으로 한 칸 움직일 때 건너뛰는 **바이트** 수 — int64 (3, 4) 는 `(32, 8)`
- **view**: 메모리를 공유하는 다른 모양의 배열. 슬라이스 · reshape 결과. 고치면 원본도 바뀐다
- **axis**: 집계할 때 **없어지는 축**. `sum(axis=0)` 은 axis 0 이 사라져 열마다 하나
- **브로드캐스팅(broadcasting)**: shape 를 오른쪽 끝부터 비교해 같거나 한쪽이 1 이면, 1 인 쪽을 늘려 계산하는 규칙

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `np.array()` | `np.array([1, 2, 3], dtype=np.float32)` | 리스트 → ndarray |
| `np.zeros()` | `np.zeros((3, 4))` | 0 으로 채운 배열 (`np.ones` 는 1) |
| `np.arange()` | `np.arange(0, 10, 2)` | 범위 배열 (stop 미포함) |
| `np.linspace()` | `np.linspace(0, 1, 5)` | 구간을 n 등분한 점 (끝 포함) |
| `ndarray.reshape()` | `A.reshape(4, 3)` · `A.reshape(-1)` | 모양 바꾸기 — 대부분 view |
| `np.random.default_rng()` | `rng = np.random.default_rng(42)` | seed 고정 난수 생성기 |

**예제 코드가 하는 일**
| 예제 | 하는 일 |
|---|---|
| ndarray 의 정체 | `np.arange(12).reshape(3, 4)` 의 shape · strides · itemsize 출력, reshape 한 B 를 고치면 A 도 바뀌는지(`np.shares_memory`), `.copy()` 는 안 바뀌는지 확인 |
| 인덱싱 · 슬라이싱 · reshape | `A[1, 2]` = **6**, `A[0]`, `A[:, 1]`, `A[1:, 2:]`, `A[A > 6]` 불리언 마스크 |
| 그림으로 보는 브로드캐스팅 | `(3, 4) + (4,)` — 모든 행에 `[10, 20, 30, 40]` 을 더함 |
| shape 맞히기 10문제 | `A = np.zeros((3, 4))` 에 `.T` · `reshape` · `sum(axis)` · 브로드캐스팅을 한 결과 shape 를 맞힘 |

**핵심 내용**

#### ndarray 의 정체 — 한 줄 메모리 + 읽는 규칙
> 숫자는 메모리에 한 줄로 있고, shape · strides 가 "몇 칸씩 건너 읽을지" 를 정해 다차원처럼 보여 준다
- **`np.arange(12).reshape(3, 4)`** → 12개를 한 줄로, shape **(3, 4)** · strides **(32, 8)**
- **strides 계산** → int64 는 원소 하나 **8바이트** → 열 방향 **8**, 행 방향 4 × 8 = **32**
- **`A[i, j]` 의 위치** → i × 32 + j × 8 바이트 (C 2차원 배열 주소 계산과 같다)
- **속성** → `ndim` 차원 수 · `shape` 모양 · `size` 원소 수 · `dtype` 타입
- ⚠ `np.array([1, 2, 3])` 은 **int64** — 0.5 를 대입하면 **0** 으로 잘린다 → `dtype=float` 또는 `[1., 2., 3.]`

#### view vs copy
> reshape · 슬라이스는 **읽는 규칙만 바꾼 view** — 메모리를 공유하므로 고치면 원본도 바뀐다
- **`B = A.reshape(4, 3); B[0, 0] = 100`** → `A[0, 0]` 도 **100**
- **공유 확인** → `np.shares_memory(A, B)` → True
- **독립 사본** → `A.reshape(4, 3).copy()` — 고쳐도 A 는 그대로
- ⚠ 슬라이스 `A[1:, 2:]` 도 view → 원본을 지키려면 `.copy()`

#### 인덱싱 · 슬라이싱 · 마스크
> `A[행, 열]` — `:` 는 "그 축 전체"
- **`A[1, 2]`** → 1행 2열 한 칸 (**6**)
- **`A[0]`** → 0행 전체 · **`A[:, 1]`** → 1열 전체 · **`A[1:, 2:]`** → 부분 행렬
- **`A[A > 6]`** → 조건이 참인 원소만 → `[7 8 9 10 11]` (Day 3 ReLU 역전파의 mask)
- ⚠ **(3,) 와 (3, 1) 은 다른 shape** — 1차원 벡터는 행도 열도 아니다

#### axis — 없어지는 축
> `sum(axis=k)` 는 k 번 축을 따라 더해 **그 축을 없앤다**
- **(3, 4) 에서 `sum(axis=0)`** → 위→아래로 더해 **(4,)** — 열마다 하나
- **(3, 4) 에서 `sum(axis=1)`** → 왼→오른쪽으로 더해 **(3,)** — 행마다 하나
- **`keepdims=True`** → 없앨 축을 크기 **1** 로 남김 → `(3, 1)` — 원래 배열과 다시 계산(브로드캐스팅)할 때
- **신경망** → 배치 축(**axis 0**)으로 평균 내는 일이 많다 (Day 3 손실 평균 · Day 4 BatchNorm)

#### 브로드캐스팅
> shape 를 **오른쪽 끝부터** 비교해 각 축이 ① 같거나 ② 한쪽이 1 이면 계산 가능 — 1 인 쪽이 늘어난다
| 식 | 맞춰 보기 | 결과 |
|---|---|---|
| (3, 4) + (4,) | (3, 4) + (1, 4) | **(3, 4)** — 모든 행에 더함 |
| (3, 1) + (1, 4) | 양쪽이 늘어남 | **(3, 4)** |
| (3, 4) + (3,) | 4 와 3 이 다름 | ❌ 오류 |
- **실제로 복사하지 않는다** → 복사한 것처럼 계산 (메모리 절약)
- **신경망 `X @ W + b`** → 편향 b **(H,)** 가 모든 샘플(행)에 더해지는 것이 이 규칙

**기본 사용형태**
```python
import numpy as np
rng = np.random.default_rng(42)
A = np.arange(12).reshape(3, 4)      # shape (3, 4), strides (32, 8)
A.sum(axis=0)                        # (4,)  열마다
A.mean(axis=1, keepdims=True)        # (3, 1)
A + np.array([10, 20, 30, 40])       # (3, 4) + (4,) 브로드캐스팅
B = A[1:, 2:].copy()                 # 독립 사본
x = np.array([1.0, 2.0, 3.0])        # 실수 계산은 float 로
```

#### 이 교시에서 답하는 질문
2교시에서 리스트가 숫자 계산에 느리다는 것을 봤다. 이 교시는 신경망의 모든 숫자를 담을 그릇, **NumPy 배열(ndarray)** 이 메모리에 어떻게 놓이는지 보고, 그 구조 덕분에 가능한 **인덱싱 · reshape · 브로드캐스팅**을 익힌다.

#### 개념 1 · ndarray = 한 줄 메모리 + 읽는 규칙
ndarray 는 같은 타입(dtype)의 값을 **메모리에 한 줄로 연속** 놓고, 그것을 몇 행 몇 열로 읽을지(shape)와 한 칸 이동할 때 몇 바이트를 건너뛸지(strides)를 함께 가진다.

![12개 값이 메모리에 한 줄로 놓이고, shape (3, 4) 와 strides (32, 8) 로 표처럼 읽힌다](assets/fig/nn/d1-strides.svg)

- `np.arange(12).reshape(3, 4)` 는 int64(8바이트) 12개. strides = **(32, 8)**: 옆 칸은 8바이트, 아래 칸은 4칸 × 8 = 32바이트 이동.
- `A[1, 2]` 는 1×32 + 2×8 = 48바이트 위치의 값 **6** 이다.
- **reshape 은 대부분 view** — 같은 메모리를 다른 shape 로 읽을 뿐이라 복사가 없어 빠르지만, view 를 고치면 원본도 바뀐다. 독립 사본은 `.copy()`.

#### 개념 2 · 인덱싱 · 슬라이싱 · 불리언 마스크
| 표현 | 뜻 | A = arange(12).reshape(3, 4) 의 결과 |
|---|---|---|
| `A[1, 2]` | 1행 2열 | 6 |
| `A[0]` | 0행 전체 | [0 1 2 3] |
| `A[:, 1]` | 1열 전체 | [1 5 9] |
| `A[1:, 2:]` | 부분 행렬 | [[6 7] [10 11]] |
| `A[A > 6]` | 조건에 맞는 원소만 | [7 8 9 10 11] |

불리언 마스크(`A > 6` 이 만드는 True/False 배열)는 Day 3 ReLU 역전파에서 "막힌 자리" 를 기억하는 데 쓰인다.

#### 개념 3 · 브로드캐스팅 — 모양이 다른 배열끼리 계산하기
(3, 4) 배열에 (4,) 배열을 더하면, 작은 쪽이 **행 방향으로 복사된 것처럼** 늘어나 계산된다. 실제로 복사하지는 않는다.

- `axis` 를 지정한 집계(`sum(axis=1)`)는 그 축을 없앤다. `keepdims=True` 를 주면 크기 1 로 남겨 다시 브로드캐스팅할 수 있다 — Day 2 softmax 에서 필수.

print(A.shape, A.strides, A.dtype)
B = A.reshape(4, 3); B[0, 0] = 100
print(A[0, 0], np.shares_memory(A, B))

- **어떤 개념**: 개념 1 — 한 줄 메모리 + 읽는 규칙, reshape = view.
- **출력**: `(3, 4) (32, 8) int64`, `100 True` (원본도 바뀜)

```python

b = np.array([10, 20, 30, 40])
print(A + b)
```
- **무엇을 하나**: (3, 4) 행렬의 모든 행에 b 를 더한다.
- **어떤 개념**: 개념 3 — 브로드캐스팅 = 신경망의 "+ 편향".

### 4교시 · 벡터화

**키워드**: `벡터화`, `C · BLAS`, `원소별 연산`, `@ 행렬곱`, `C[i][j] = 행 · 열 내적`, `(N, D) @ (D, H) → (N, H)`, `for 루프 vs @`, `원소별 곱 *`, `core dimension mismatch`, `axis 집계`, `argmax`

**개요**: 신경망은 곱셈-덧셈을 수백만~수십억 번 한다. ① **벡터화**는 Python for 루프 대신 NumPy 연산 한 번으로 배열 전체를 처리하는 것 — 내부가 C · BLAS 라 수백 배 빠르다. ② 행렬곱 `C = A @ B` 의 한 칸은 **A 의 행과 B 의 열의 내적**이고, 안쪽 차원이 같아야 하며 그 축은 사라진다. ③ `mean` · `sum` · `argmax` 는 axis 로 "무엇을 기준으로" 집계할지 정한다.

**핵심 용어**
- **벡터화(vectorization)**: 반복문을 NumPy 내부(C · BLAS)로 넘겨 배열 전체를 한 번에 계산하는 것
- **원소별 연산(element-wise)**: 같은 자리끼리 계산 — `x * 2`, `x ** 2`, `np.exp(x)`, `A * B`
- **행렬곱(matrix multiplication)**: C[i][j] = Σ_k A[i][k] · B[k][j]. A 의 열 수 = B 의 행 수여야 한다
- **BLAS**: C · Fortran 으로 최적화된 선형대수 라이브러리. `@` 가 내부에서 호출한다

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `A @ B` | `C = A @ B` | 행렬곱 (`np.dot(A, B)` 와 같음) |
| `np.sum()` | `A.sum(axis=0)` | 합계 (axis 로 기준 축 지정) |
| `np.mean()` | `A.mean(axis=1, keepdims=True)` | 평균 |
| `np.argmax()` | `scores.sum(axis=1).argmax()` | 최댓값의 인덱스 |

**예제 코드가 하는 일**
| 예제 | 하는 일 |
|---|---|
| 들어가며 | x × 2, x², `np.sqrt(x)`, `np.exp(x)` — 루프 없는 원소별 연산 |
| 행렬곱 for 루프 vs @ | 3중 for 루프 `matmul_loop` 를 완성해 `A @ B` 와 같은지 확인, 200×200 에서 두 방식의 시간 비교 |
| axis 를 쓰는 집계 함수 | 학생 5 × 과목 3 점수표에서 과목별 평균 **[72.6, 80.4, 78.0]**, 학생별 총점 **[240, 240, 225, 275, 175]**, 1등 = **3번** |

**핵심 내용**

#### 벡터화 — 루프를 NumPy 안으로
> for 루프 대신 배열 연산 한 줄 → 실제 반복은 컴파일된 C 코드가 한다
- **원소별 연산** → `x * 2`, `x ** 2`, `np.sqrt(x)`, `np.exp(x)` — 루프 없이 배열 전체
- **왜 필요** → 200×200 행렬곱만 곱셈 **800만** 번, MNIST 학습은 **수십억** 번
- **속도** → 순수 Python 루프보다 **수백~수천 배** 빠름 (200×200: 루프는 초 단위, `@` 는 ms 이하)
##### 자세히
| 순수 Python for | NumPy `@` |
|---|---|
| 곱셈마다 인터프리터가 명령을 해석 | 컴파일된 BLAS 함수 **한 번** 호출 |
| 원소마다 타입 확인 · 객체 생성 | 같은 dtype 이라 확인 불필요 |
| 참조를 따라 메모리 여기저기 접근 | 연속 메모리를 캐시 · SIMD 로 한꺼번에 |

#### 행렬곱 한 칸 = 행 · 열 내적
> C[i][j] = A 의 i 행과 B 의 j 열을 원소끼리 곱해 더한 값
- **3중 for 루프** → `C[i][j] += A[i][k] * B[k][j]` (i: 행, j: 열, k: 짝지어 곱할 안쪽 축)
- **shape 규칙** → (N, **D**) @ (**D**, H) → **(N, H)** — 안쪽 D 가 같아야 하고, 계산 후 사라진다
- **`A @ B` = `np.dot(A, B)`** → 2차원이면 둘이 같다
- ⚠ `matmul: … mismatch in its core dimension` → **안쪽 차원이 다르다** → 두 배열의 shape 부터 출력

#### 원소별 곱 * 과 행렬곱 @ 은 다르다
> `*` 는 같은 자리끼리, `@` 는 행 · 열 내적
- **`A * B`** → shape 가 같아야(또는 브로드캐스팅) 하고 결과 shape 도 같다
- **`A @ B`** → 안쪽 차원이 같아야 하고 결과는 바깥쪽 (N, H)
- ⚠ shape 가 같으면 `*` 도 **오류 없이 돌아가서** 버그를 찾기 어렵다 — 행렬곱이면 반드시 `@`

#### axis 로 집계하기
> 점수표 `scores[i, j]` = i 번 학생의 j 과목 점수 (5, 3)
- **과목별 평균** → `scores.mean(axis=0)` → **(3,)** = [**72.6**, **80.4**, **78.0**]
- **학생별 총점** → `scores.sum(axis=1)` → **(5,)** = [240, 240, 225, **275**, 175]
- **1등 학생** → `scores.sum(axis=1).argmax()` → **3** (값이 아니라 **위치**)
- **학생별 평균 빼기** → `scores - scores.mean(axis=1, keepdims=True)` — (5, 1) 로 남겨야 (5, 3) 과 브로드캐스팅
- ⚠ `keepdims` 없이 `scores - scores.mean(axis=1)` → (5, 3) − (5,) → 오른쪽 축 3 과 5 가 달라 **오류**

**기본 사용형태**
```python
C = A @ B                                      # (N, D) @ (D, H) → (N, H)
scores.mean(axis=0)                            # 과목별 평균 (3,)
scores.sum(axis=1)                             # 학생별 총점 (5,)
scores.sum(axis=1).argmax()                    # 1등 학생 번호 → 3
scores - scores.mean(axis=1, keepdims=True)    # 학생별 평균을 뺀 점수
```

#### 이 교시에서 답하는 질문
NumPy 배열이 있어도 파이썬 for 루프로 원소를 하나씩 계산하면 여전히 느리다. 이 교시는 루프 대신 **배열 전체를 한 번에 계산하는 벡터화**가 왜 빠른지, 그리고 신경망에서 가장 많이 쓰는 두 가지 — **행렬곱 `@`** 과 **axis 집계** — 를 본다.

#### 개념 1 · 벡터화 — 루프를 C 로 내려보낸다
`x * 2`, `x ** 2`, `np.exp(x)` 처럼 배열에 연산을 쓰면 원소마다 같은 계산이 한 번에 된다. 반복 자체는 NumPy 내부(C 코드, CPU 의 SIMD 명령)에서 일어나므로, 파이썬 루프를 도는 비용 — 2교시의 "참조 따라가기 → 타입 확인 → 새 객체" — 이 사라진다.
- 같은 200×200 행렬곱을 파이썬 3중 for 루프와 `A @ B` 로 비교하면 **수천 배** 차이가 난다 (정확한 배수는 CPU 마다 다름).
- 원칙: **신경망 코드에는 파이썬 for 루프로 원소를 돌지 않는다.** 반복은 미니배치나 epoch 처럼 큰 단위에만.

#### 개념 2 · 행렬곱 C = A @ B
C[i][j] = Σₖ A[i][k] × B[k][j] — A 의 i 행과 B 의 j 열을 짝지어 곱해 더한 값(내적)이다.
- shape 규칙: (n, m) @ (m, p) = (n, p). **안쪽 m 이 같아야 하고**, 계산 뒤 사라진다.
- 신경망의 한 층 계산 `X @ W` 가 바로 이것이다 (5교시에서 자세히).

#### 개념 3 · axis 를 쓰는 집계 — 어느 방향으로 모으나
`sum` · `mean` · `max` · `argmax` 에 axis 를 주면 그 축을 따라 모으고, 그 축은 사라진다.
- (학생 5, 과목 3) 성적표에서 `mean(axis=0)` 은 **세로로** 모아 과목별 평균 (3,), `sum(axis=1)` 은 **가로로** 모아 학생별 총점 (5,).
- `argmax` 는 최댓값의 **위치**를 돌려준다. 신경망 출력(클래스별 점수)에서 예측 클래스를 고를 때 그대로 쓴다.
- 학생별 평균을 빼려면 `mean(axis=1, keepdims=True)` (5, 1) 로 남겨야 (5, 3) 과 브로드캐스팅된다.

#### 코드로 확인

### 5교시 · 선형대수

**키워드**: `내적`, `a · b = ‖a‖‖b‖cos θ`, `노름`, `코사인 유사도`, `뉴런 = 닮음 측정기`, `선형 변환`, `회전 행렬 R(θ)`, `확대 S`, `행렬의 열 = 기준 벡터가 가는 곳`, `det`, `P @ M.T`, `X @ W + b`

**개요**: 신경망 한 층이 하는 일을 기하학으로 본다. ① **내적**은 두 벡터가 얼마나 같은 방향인가를 잰다 — 뉴런의 가중합 w · x 는 입력이 가중치 패턴과 얼마나 닮았는지 재는 것이다. ② **행렬곱은 선형 변환** — 공간을 회전 · 확대 · 찌그러뜨린다. 행렬의 각 열은 기준 벡터가 옮겨 가는 곳이다. ③ 신경망 한 층 `X (N, D) @ W (D, H) + b (H,) = Y (N, H)` 는 데이터를 새 공간으로 옮기는 변환이다.

**핵심 용어**
- **내적(dot product)**: a · b = Σ aᵢbᵢ = ‖a‖‖b‖cos θ. 같은 방향이면 크고, **직각이면 0**, 반대면 음수
- **노름(norm)**: 벡터의 길이 ‖a‖ = √(a · a)
- **코사인 유사도(cosine similarity)**: (a · b) / (‖a‖‖b‖) = cos θ. 길이와 무관하게 방향만 비교 (−1 ~ 1)
- **선형 변환(linear transformation)**: 행렬곱으로 공간을 바꾸는 것. 행렬의 열 = 기준 벡터 e₁ = (1, 0), e₂ = (0, 1) 이 옮겨 가는 곳
- **행렬식(det)**: 변환 후 넓이가 몇 배가 되는지. **det = 0** 이면 평면이 직선으로 납작해져 정보가 사라진다

**새로 나온 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `np.dot()` | `np.dot(a, b)` | 내적 (1차원끼리는 스칼라) |
| `np.linalg.norm()` | `np.linalg.norm(a)` | 벡터 길이 |
| `ndarray.T` | `P @ R.T` | 전치 (행 ↔ 열) |

**예제 코드가 하는 일**
| 예제 | 하는 일 |
|---|---|
| 그림으로 보는 내적 | a = [1, 2, 2], b = [2, 0, 1] 의 내적 **4** (`a @ b` · `np.dot`), ‖a‖ = **3** |
| 행렬곱 = 선형 변환 | 회전 행렬 `rot(θ)` 를 완성하고, 정사각형 + 화살표 점들을 30° 회전 · (2, 0.5) 확대 · 회전 후 확대한 그림 |
| 행렬곱의 shape 규칙 | 입력 4샘플 × 특징 3 → 출력 2 층: W (3, 2), b (2,), Y (4, 2) |

**핵심 내용**

#### 내적 = 닮음 측정기
> a · b 는 "b 를 a 방향으로 내린 그림자 길이 × a 의 길이" — 같은 방향일수록 크다
- **계산** → a = [1, 2, 2], b = [2, 0, 1] → 1·2 + 2·0 + 2·1 = **4**, ‖a‖ = √9 = **3**
- **부호** → 같은 방향 **양수** · 직각 **0** · 반대 **음수**
- **뉴런 하나** → 가중합 w · x = 입력 x 가 가중치 패턴 w 와 **얼마나 닮았는지**
- **코사인 유사도** → `(a @ b) / (norm(a) * norm(b))` — 길이를 나눠 방향만 비교

#### 행렬곱 = 선형 변환
> 행렬을 곱하면 공간 전체가 회전 · 확대 · 찌그러진다 — 행렬의 **열**이 기준 벡터의 새 위치
- **회전** → R(θ) = [[cos θ, −sin θ], [sin θ, cos θ]]
- **확대** → S = [[sx, 0], [0, sy]] — S = [[2, 0], [0, 0.5]] 는 가로 2배 · 세로 절반
- **확인** → (1, 0) 을 90° 회전하면 **(0, 1)**
- **순서** → `S @ rot(θ)` = 먼저 회전, 그다음 확대 (오른쪽 행렬이 먼저 적용)
- **det = 0** → 평면이 직선으로 납작 → 정보 손실 (되돌릴 수 없다)

#### 점이 행으로 쌓이면 P @ M.T
> 점 N 개를 행 하나에 하나씩 쌓은 P (N, 2) 에 변환 M (2, 2) 을 적용 = `P @ M.T`
- **이유** → 점 하나 p (열 벡터) 의 변환은 M p, 이걸 행으로 눕히면 pᵀ Mᵀ → 모두 쌓으면 P Mᵀ
- **`ndarray.T`** → 행 ↔ 열을 바꾼 view
- ⚠ `M @ P` → (2, 2) @ (N, 2) → shape 가 **맞지 않는다**
- ⚠ 1차원 (3,) 끼리 `@` → **스칼라**(내적). 행렬이 필요하면 `reshape(1, 3)`

#### 신경망 한 층 미리 보기
> X (N, D) @ W (D, H) + b (H,) = Y (N, H) — 안쪽 D 가 같아야 하고 결과는 바깥쪽
- **N** → 샘플(배치) 수 · **D** → 입력 특징 수 · **H** → 출력(뉴런) 수
- **입력 4샘플 × 특징 3 → 출력 2** → W **(3, 2)**, b **(2,)**, Y **(4, 2)**
- **b 가 더해지는 원리** → (4, 2) + (2,) 브로드캐스팅 (3교시)
##### 자세히
- X 의 행 4개 = 샘플 4개, 열 3개 = 특징 3개 · b 는 브로드캐스팅으로 모든 행에 더해짐

**기본 사용형태**
```python
a @ b                                   # 내적 (1차원끼리 → 스칼라)
np.linalg.norm(a)                       # 길이
(a @ b) / (np.linalg.norm(a) * np.linalg.norm(b))   # 코사인 유사도
Q = P @ M.T                             # 점 (N, 2) 을 M 으로 변환
X = rng.normal(size=(4, 3)); W = rng.normal(size=(3, 2)); b = np.zeros(2)
Y = X @ W + b                           # (4, 2)
```

#### 이 교시에서 답하는 질문
신경망의 계산은 거의 전부 벡터와 행렬의 곱이다. 이 교시는 **내적**이 "두 벡터가 얼마나 같은 방향인가" 를 재는 값이라는 것, **행렬곱**이 공간을 변환하는 것이라는 것, 그리고 신경망 한 층 `Y = XW + b` 의 **shape 규칙**을 본다.

#### 개념 1 · 내적 — 두 벡터가 얼마나 같은 방향인가
> a · b = Σ aᵢbᵢ = ‖a‖ × ‖b‖ cos θ

![내적 = a 의 길이 × (b 를 a 위로 내린 그림자 길이)](assets/fig/nn/d1-dot.svg)

- 같은 방향이면 크다(cos 1), 수직이면 0(cos 0), 반대 방향이면 음수(cos −1).
- **코사인 유사도** = a·b / (‖a‖‖b‖) 는 길이를 빼고 방향만 비교한다 (−1 ~ 1).
- 뉴런의 가중합 x·W 도 내적이다: 입력 x 가 가중치 W 와 같은 방향일수록 큰 값을 낸다 — 뉴런이 "이런 입력 패턴" 에 반응하는 원리.

#### 개념 2 · 행렬곱 = 선형 변환
점(벡터)에 행렬을 곱하면 공간이 돌거나(회전) 늘어나는(스케일) 변환이 된다.
- **기준 벡터 e₁ = (1, 0), e₂ = (0, 1) 이 옮겨 가는 곳이 행렬의 열**이다. 예: 90° 회전 행렬 [[0, −1], [1, 0]] 은 e₁ → (0, 1), e₂ → (−1, 0).
- 변환을 연달아 하면 행렬을 곱한 것과 같다 (회전 후 스케일 = S @ R).
- 신경망의 각 층도 입력 공간을 변환한다. Day 2 3교시의 "은닉층은 공간을 바꾼다" 의 수학적 바탕이다.

#### 개념 3 · 신경망 한 층의 shape 규칙
> Y = X @ W + b,  (N, D) @ (D, M) + (M,) = (N, M)

![신경망 한 층 — 행 = 샘플, 열 = 특징. 안쪽 D 가 같아야 하고 b 는 모든 행에 더해진다](assets/fig/nn/d1-matmul.svg)

- **행 = 샘플(N개), 열 = 특징(D개)**. W 는 (입력 특징 수, 출력 수), b 는 (출력 수,).
- 예: 샘플 4개 · 특징 3개를 출력 2개로 → W (3, 2), b (2,), Y (4, 2).
- b 는 브로드캐스팅(3교시)으로 모든 행에 더해진다.

#### 코드로 확인
```python
a = np.array([1.0, 2.0, 2.0]); b = np.array([2.0, 0.0, 1.0])
print(a @ b, np.linalg.norm(a))
def cos_sim(a, b): return (a @ b) / (np.linalg.norm(a) * np.linalg.norm(b))
```
- **무엇을 하나**: 내적, 벡터 길이, 코사인 유사도를 계산한다.
- **어떤 개념**: 개념 1.
- **출력**: `4.0 3.0`, cos_sim(a, b) ≈ `0.596`

```python
X = rng.normal(size=(4, 3))
W = rng.normal(size=(3, 2))
b = np.zeros(2)
Y = X @ W + b
print(Y.shape)
```
- **무엇을 하나**: 샘플 4개 · 특징 3개를 출력 2개로 바꾸는 한 층을 계산한다.
- **어떤 개념**: 개념 3 — (N, D) @ (D, M) + (M,) = (N, M).
- **출력**: `(4, 2)`

#### 한 번에 정리
- 내적 = 같은 방향일수록 큰 값. 코사인 유사도 = 방향만 비교.
- 행렬 = 공간 변환. 행렬의 열 = 기준 벡터가 옮겨 가는 곳.
- 신경망 한 층 Y = XW + b: (N, D) @ (D, M) + (M,) = (N, M), 행 = 샘플.
- ⚠ 순서는 `X @ W` — `W @ X` 는 shape 오류이거나(정사각이면) 조용히 틀린 값.

### 6교시 · 미분과 기울기

**키워드**: `순간 변화율`, `할선 → 접선`, `중앙 차분`, `h = 1e-4`, `반올림 오차`, `편미분`, `기울기(gradient) ∇f`, `가장 가파른 오르막`, `−∇f`, `numerical_gradient`, `되돌리기`, `gradient check`

**개요**: 학습의 고리에서 "어느 쪽으로 바꾸면 손실이 줄어드나" 를 알려 주는 것이 미분이다. ① 미분 = h → 0 의 순간 변화율, 컴퓨터에서는 **중앙 차분** (f(x+h) − f(x−h)) / 2h 로 근사하고 **h ≈ 1e-4** 를 쓴다. ② 변수가 여러 개면 하나씩만 움직이는 **편미분**을 모은 벡터가 **기울기 ∇f** — 함수값이 가장 빨리 커지는 방향이고, 그 반대(−∇f)로 가면 가장 빨리 작아진다(경사하강의 원리). ③ 임의 shape 배열의 기울기를 구하는 `numerical_gradient` 는 Day 3 역전파 검증의 정답지가 된다.

**핵심 용어**
- **미분(derivative)**: 순간 변화율 f'(x) = lim (f(x+h) − f(x)) / h. 그래프에서는 그 점의 **접선의 기울기**
- **수치 미분(numerical differentiation)**: 아주 작은 h 로 미분을 근사 — 중앙 차분이 오차가 작다
- **중앙 차분(central difference)**: (f(x+h) − f(x−h)) / 2h. 근사 오차가 **h²** 에 비례
- **편미분(partial derivative)**: 변수 하나만 움직이고 나머지는 고정한 미분
- **기울기(gradient, ∇f)**: 편미분을 모은 벡터. 함수값이 **가장 빨리 커지는 방향**. 등고선에 수직

**이 교시에서 만드는 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `numerical_diff()` | `numerical_diff(f, x, h=1e-4)` | 중앙 차분으로 f'(x) 근사 |
| `numerical_gradient()` | `numerical_gradient(f, x, h=1e-4)` | 임의 shape 배열 x 에 대한 기울기 — Day 3 gradient check 의 정답지 |

**예제 코드가 하는 일**
| 예제 | 하는 일 |
|---|---|
| 그림으로 보는 미분 | `numerical_diff` 를 완성해 (x²)' at 3 = **6**, sin'(0) = **1** 확인, h 를 줄여 가며 오차 출력, x = 1 에서 접선 그리기 |
| numerical_gradient 의 동작 순서 | f = Σx² 의 기울기 [3, 4] → **[6, 8]**, 2차원 M 도 2M, −기울기 화살표가 (0, 0) 을 향하는 벡터장 |

**핵심 내용**

#### 미분 = 순간 변화율
> 두 점을 잇는 할선의 기울기에서 간격 h 를 0 으로 줄이면 접선의 기울기 = 미분값
- **할선의 기울기** → "평균 변화율" (f(x+h) − f(x)) / h
- **h → 0** → 할선이 접선으로 다가간다
- **신경망에서의 뜻** → "파라미터를 아주 조금 바꾸면 손실이 **얼마나** 바뀌나"

#### 중앙 차분과 h 의 크기
> f'(x) ≈ (f(x+h) − f(x−h)) / 2h, h ≈ **1e-4** — 너무 크면 근사 오차, 너무 작으면 반올림 오차
- **확인** → (x²)' at 3 = **6** · sin'(0) = cos 0 = **1**
- **중앙 차분** → 근사 오차가 **h²** 에 비례 → 한쪽 차분 (f(x+h) − f(x)) / h 보다 훨씬 정확
- **h 가 너무 작으면** → float64 유효 자릿수(약 **16자리**) 때문에 반올림 오차 — x² at 3 에서 h = 1e-12 → 오차 **5×10⁻⁴**, h = 1e-15 → **0.67** (직접 실행)
- **float32** → `np.float32(1e-50)` = **0.0** — 아예 0 이 된다
- ⚠ h 를 "작을수록 정확" 으로 생각해 1e-50 처럼 쓰면 결과가 엉망 → **1e-4**

#### 기울기 = 가장 가파른 오르막
> 편미분을 모은 벡터 ∇f 는 함수값이 가장 빨리 커지는 방향 — 반대 −∇f 로 가면 가장 빨리 작아진다
- **편미분** → x₀ 만 움직이고 x₁ 은 고정해 미분 (그다음 반대로)
- **예** → f = x₀² + x₁² → ∇f = (**2x₀**, **2x₁**)
- **그림** → 기울기 화살표는 **등고선에 수직**, −∇f 화살표는 모두 최소점 (0, 0) 을 향한다
- **경사하강의 원리** → 매번 −∇f 방향으로 조금씩 → 골짜기 바닥 (8교시)
- ⚠ 기울기 방향으로 **더하면** 함수값(손실)이 커진다 — 경사하강은 **빼기**

#### numerical_gradient — 원소마다 중앙 차분
> 배열의 원소를 하나씩 ±h 로 흔들어 f 를 두 번 계산하고, 끝나면 **원래 값으로 되돌린다**
- **순서** → `orig = x[idx]` → `x[idx] = orig + h` 로 f → `orig - h` 로 f → `(fxh1 - fxh2) / (2*h)` → **`x[idx] = orig`**
- **모든 칸 순회** → `np.nditer(x, flags=["multi_index"])` — 1차원 · 2차원 어떤 shape 든
- **확인** → f = Σx², x = [3, 4] → **[6, 8]**, 2차원 M → **2M**
- **비용** → 원소 하나당 f 를 **2번** → 파라미터가 많으면 매우 느리다 (Day 3 역전파가 필요한 이유)
- ⚠ **정수 배열**이면 `orig + h` 가 정수로 잘려 기울기 **0** → `np.array([3.0, 4.0])` 처럼 실수로
- ⚠ 되돌리기를 빼먹으면 → 다음 원소를 흔들 때 앞 원소가 바뀐 상태라 **기울기가 틀린다**

**기본 사용형태**
```python
def numerical_diff(f, x, h=1e-4):
    return (f(x + h) - f(x - h)) / (2 * h)

def numerical_gradient(f, x, h=1e-4):
    grad = np.zeros_like(x)
    it = np.nditer(x, flags=["multi_index"])
    while not it.finished:
        idx = it.multi_index
        orig = x[idx]
        x[idx] = orig + h; fxh1 = f(x)
        x[idx] = orig - h; fxh2 = f(x)
        grad[idx] = (fxh1 - fxh2) / (2 * h)
        x[idx] = orig                       # 되돌리기!
        it.iternext()
    return grad
```

**상세 학습**

#### 이 교시에서 답하는 질문
학습의 고리에서 "기울기" 단계는 "파라미터를 어느 쪽으로 바꾸면 손실이 줄어드나" 를 알려 준다. 이 교시는 그 답을 주는 도구, **미분**과 **기울기(gradient)** 를 직관으로 이해하고, 컴퓨터로 직접 계산하는 **수치 미분**을 만든다.

#### 개념 1 · 미분 = 아주 조금 움직였을 때의 변화율
> f′(x) = lim(h → 0) (f(x + h) − f(x)) / h

x 를 아주 조금(h) 움직였을 때 f 가 얼마나 변하는지의 비율이다. 그래프로는 그 점에서의 **접선의 기울기**다.

![x = 1.5 에서 f(x) = x² 의 접선(기울기 3)과 할선(기울기 4) — h 를 줄이면 할선이 접선에 가까워진다](assets/fig/nn/d1-derivative.svg)

- 컴퓨터는 극한을 못 하므로 작은 h 로 근사한다: **수치 미분**. 양쪽을 보는 **중앙 차분** (f(x + h) − f(x − h)) / 2h 이 한쪽만 보는 것보다 정확하다.
- h 는 **1e-4** 정도가 좋다. 너무 작으면(1e-15) 두 함숫값이 거의 같아져 반올림 오차로 결과가 망가진다 (x² 의 x = 3 에서 오차 0.67).

#### 개념 2 · 기울기(gradient) — 변수가 여러 개일 때
변수가 여러 개면 변수마다 따로 미분(편미분)해서 벡터로 모은다.

> ∇f = (∂f/∂x₀, ∂f/∂x₁, …)

![f = x₀² + x₁² 의 등고선 — 기울기는 가장 가파른 오르막, −기울기는 바닥 쪽](assets/fig/nn/d1-gradient.svg)

- 기울기 벡터는 **가장 가파르게 올라가는 방향**을 가리킨다. 그 반대(−∇f)는 가장 가파른 내리막이다.
- 그래서 손실을 줄이려면 파라미터를 **−기울기 방향으로 조금씩** 옮기면 된다 → 8교시 경사하강.
- 예: f = x₀² + x₁² 의 점 (3, 4) 에서 ∇f = (2x₀, 2x₁) = (6, 8).

#### 개념 3 · numerical_gradient — 파라미터 하나씩 흔들어 보기
배열의 원소마다 "그 원소만 +h, −h 로 움직여 f 를 두 번 계산" 하고, 계산이 끝나면 **원래 값으로 되돌린다**. 이 함수는 Day 3 까지 계속 쓰이며, Day 3 에서는 역전파가 맞는지 확인하는 정답지(gradient check)가 된다.
- 파라미터가 P 개면 f 를 2P 번 계산해야 해서 느리다 — Day 3 역전파가 필요한 이유.

#### 코드로 확인
```python
def numerical_diff(f, x, h=1e-4):
    return (f(x + h) - f(x - h)) / (2 * h)
numerical_diff(lambda x: x ** 2, 3.0)
```
- **무엇을 하나**: 중앙 차분으로 x = 3 에서 x² 의 기울기를 근사한다.
- **어떤 개념**: 개념 1 — 미분 = 변화율, 중앙 차분.
- **출력**: `6.000000000012662` (정답 2x = 6). h 를 1e-12 로 줄이면 오차 5 × 10⁻⁴, 1e-15 면 0.67 로 오히려 나빠진다.

```python
def numerical_gradient(f, x, h=1e-4):
    grad = np.zeros_like(x)
    it = np.nditer(x, flags=["multi_index"])
    while not it.finished:
        idx = it.multi_index; orig = x[idx]
        x[idx] = orig + h;  fxh1 = f(x)
        x[idx] = orig - h;  fxh2 = f(x)
        grad[idx] = (fxh1 - fxh2) / (2 * h)
        x[idx] = orig                       # 원래 값으로 되돌리기
        it.iternext()
    return grad
```
- **무엇을 하나**: 배열의 원소마다 하나씩 흔들어 그 원소 방향의 편미분을 구한다 (몇 차원 배열이든 동작).
- **어떤 개념**: 개념 2 · 3 — 기울기 = 편미분을 모은 벡터.
- **출력**: f = Σx² 에 x = [3, 4] 를 넣으면 `[6. 8.]`, 끝난 뒤 x 는 그대로 `[3. 4.]`

#### 한 번에 정리
- 미분 = 아주 조금 움직였을 때의 변화율 = 접선의 기울기. 수치 미분은 중앙 차분 + h = 1e-4.
- 기울기 ∇f = 편미분을 모은 벡터 = 가장 가파른 오르막. −∇f 로 가면 내려간다.
- numerical_gradient: 원소마다 ±h → 2번 계산 → 되돌리기. 정확하지만 느리다.
- ⚠ `x[idx] = orig` 로 되돌리지 않으면 다음 원소의 미분이 틀어진다.

### 7교시 · 확률 기초

**키워드**: `평균 · 분산 · 표준편차`, `균등분포 U(a, b)`, `정규분포 N(μ, σ²)`, `68% · 95%`, `seed`, `default_rng(42)`, `ddof=1`, `표준화 (x − μ) / σ`, `log(0) = −inf`, `eps`, `exp overflow`

**개요**: 신경망은 **난수로 가중치를 초기화**하고(Day 4) **확률로 답을 낸다**(Day 2 Softmax). ① 평균 · 분산 · 표준편차와 두 분포(평평한 **균등**, 종 모양 **정규**)를 NumPy 로 뽑아 보고, ② seed 로 결과를 **재현**하며, ③ **표준화**로 평균 0 · 표준편차 1 을 만든다. ④ Day 2 손실 함수에서 마주칠 **log(0) = −inf** 와 **exp overflow** 를 미리 본다.

**핵심 용어**
- **평균(mean, μ)**: (1/N) Σ xᵢ — `x.mean()`
- **분산(variance, σ²)**: (1/N) Σ (xᵢ − μ)² — 평균에서 얼마나 퍼졌나. `x.var()`
- **표준편차(standard deviation, σ)**: 분산의 제곱근 — `x.std()`
- **균등분포(uniform) U(a, b)**: 구간 안 모든 값이 같은 확률 — 평평한 히스토그램 (Xavier uniform 초기화)
- **정규분포(normal) N(μ, σ²)**: 평균 근처가 가장 많은 종 모양. ±1σ 약 **68%**, ±2σ 약 **95%** (He normal 초기화)
- **표준화(standardization)**: (x − μ) / σ → 평균 **0**, 표준편차 **1** (입력 정규화 · BatchNorm 의 기초)
- **seed**: 난수 생성의 출발점. 같은 seed → 같은 난수열

**핵심 내용**

#### 두 분포 — 균등과 정규
> 균등 = 구간 안 모두 같은 확률(평평), 정규 = 평균 근처가 많고 멀수록 드문 종 모양
- **균등 `rng.uniform(a, b, n)`** → 평평한 히스토그램 — Xavier uniform 초기화
- **정규 `rng.normal(μ, σ, n)`** → ±1σ 안 **68%**, ±2σ 안 **95%** — 측정 잡음 · He normal 초기화
- **표본을 늘리면** → 히스토그램 모양 · 평균 · 표준편차가 이론값에 가까워진다 (10,000개)

#### seed 와 재현성
> 같은 seed 를 주면 실행할 때마다 같은 난수가 나온다 → 실험 결과를 비교할 수 있다

- ⚠ seed 를 고정하지 않으면 실행마다 결과가 달라 **비교가 어렵다**
- ⚠ `x.std()` 는 **N** 으로 나눈 모집단 표준편차 · 표본 표준편차(N−1)는 `x.std(ddof=1)`

#### 표준화 — 평균 0, 표준편차 1
> (x − μ) / σ — 단위 · 크기가 다른 데이터를 같은 눈금으로 맞춘다
- **키 데이터** → `rng.normal(170, 8, 1000)` 을 표준화하면 평균 ≈ **0**, 표준편차 ≈ **1**

#### log 와 exp — Day 2 손실 함수의 예고편
> log 는 확률 → 손실, exp 는 점수 → 확률. 둘 다 끝에서 터지는 값이 있다
- **−log p** → 정답 확률 p 가 작을수록 손실이 **크다** (p = 1 이면 0)
- **`np.log(0)`** → **−inf** → 이후 계산이 모두 nan
- **`np.log(0 + 1e-7)`** → 약 **−16.1** — 작은 eps 를 더하면 유한한 값
- **`np.exp(1000)`** → **inf** (overflow) — Day 2 Softmax 에서 최댓값을 빼서 해결
- ⚠ 확률에 log 를 취할 때는 항상 **`+ 1e-7`**

### 8교시 · 미니 프로젝트: 경사하강법으로 최소점 찾기

**키워드**: `경사하강`, `p ← p − η∇f(p)`, `f = x² + 3y²`, `∇f = (2x, 6y)`, `학습률 η`, `수렴 · 진동 · 발산`, `y ← (1 − 6η) y`, `0 < η < 1/3`, `history (steps + 1, 2)`, `노름 > 1e6`

**개요**: 1~7교시 도구로 학습의 고리를 처음 돌린다. ① 목표 함수 f(x, y) = x² + 3y² 의 최소점 (0, 0) 을 **경사하강** p ← p − η∇f(p) 로 찾는다. ② 해석적 기울기를 6교시의 `numerical_gradient` 와 비교해 맞는지 검증한다. ③ 학습률을 0.01 · 0.1 · 0.3 · 0.35 로 바꿔 경로를 비교하면 — 작으면 느리고, 적당하면 수렴, 크면 진동 · 발산한다. 가장 가파른 방향(y)이 학습률의 상한을 정한다.

**핵심 용어**
- **경사하강법(gradient descent)**: p ← p − η∇f(p) 를 반복해 함수의 최소점을 찾는 방법
- **학습률(learning rate, η)**: 한 번에 기울기 반대 방향으로 이동하는 크기
- **해석적 기울기(analytic gradient)**: 미분 공식으로 직접 구한 기울기 — 여기서는 (2x, 6y). 빠르고 정확
- **발산(divergence)**: 갱신할수록 값이 커져 최소점에서 멀어지는 것

**이 교시에서 만드는 함수**
| 함수 | 기본형 | 용도 |
|---|---|---|
| `gradient_descent()` | `gradient_descent(grad, init, lr, steps)` | init 에서 steps 번 갱신, 출발점 포함 경로 (steps+1, 2) 반환. 노름 > 1e6 이면 발산으로 멈춤 |

**예제 코드가 하는 일**
| 예제 | 하는 일 |
|---|---|
| 과제 1 — 목표 함수와 해석적 기울기 | `f(p)` = x² + 3y², `grad_f(p)` = (2x, 6y) — f(1, 2) = **13**, ∇f(1, 2) = **(2, 12)** |
| 과제 2 — 수치 기울기와 비교 | p = (1.5, −2) 에서 `numerical_gradient` 와 해석 기울기의 최대 오차 (< **1e-6**) |
| 과제 3 — gradient_descent | (−4, 2) 에서 lr = 0.1 로 100스텝 → 끝점 노름 < **1e-3**, lr = 0.35 면 200스텝 뒤 노름 > **1e3** (발산) |
| 과제 4 — 학습률 비교 | lr 0.01 · 0.1 · 0.3 · 0.35 로 30스텝씩 경로를 등고선 위에 그림 |

**핵심 내용**

#### 경사하강 한 걸음
> 기울기의 반대 방향으로 학습률만큼 이동: p ← p − η ∇f(p)
- **목표 함수** → f = x² + 3y² → ∇f = (**2x**, **6y**), 최소점 (0, 0), f = 0
- **p₀ = (−4, 2), η = 0.1** → ∇f = (−8, 12) → η∇f = (−0.8, 1.2) → p₁ = **(−3.2, 0.8)**
- **y 가 먼저 빠르게 줄어든다** → y 방향(3y²)이 x 방향보다 **3배** 가파르다
- **`gradient_descent()`** → 이 걸음을 steps 번 반복하며 위치를 history 에 모은다 → shape **(steps + 1, 2)**
- ⚠ `p -= lr * grad(p)` 처럼 **제자리에서** 바꾸면서 `history.append(p)` 하면 history 의 모든 칸이 같은 배열(마지막 값) → **`p.copy()`** 를 넣는다 (2교시 가변 객체)

#### 해석 기울기 vs 수치 기울기
> 공식으로 구한 기울기를 수치 미분과 비교해 맞는지 확인한다 — Day 3 gradient check 의 축소판
- **해석 기울기** → 빠르고 정확하지만 공식이 틀릴 수 있다
- **수치 기울기** → 느리지만 거의 확실 → **정답지**
- **기준** → 최대 오차 < **1e-6** 이면 통과

#### 학습률과 수렴 조건
> 매 스텝 x ← (1 − 2η) x, y ← (1 − 6η) y — 곱하는 수의 **절댓값이 1 보다 작아야** 수렴
| η | x 에 곱하는 수 1 − 2η | y 에 곱하는 수 1 − 6η | 30스텝 결과 (직접 실행) |
|---|---|---|---|
| 0.01 | 0.98 | 0.94 | 느림 — f ≈ **5.05**, 최소점에 못 닿음 |
| 0.1 | 0.8 | 0.4 | 빠르게 수렴 — f ≈ **2.5×10⁻⁵** |
| 0.3 | 0.4 | **−0.8** | y 가 부호를 바꾸며 **지그재그**로 수렴 |
| 0.35 | 0.3 | **−1.1** | y 가 커지며 **발산** (y ≈ **34.9**) |
- **곱하는 수 해석** → 0 ~ 1 사이면 줄어듦 · 음수면 부호가 바뀌며 진동 · 절댓값 > 1 이면 커짐(발산)
- **경계** → |1 − 6η| < 1 → **0 < η < 1/3** — 가장 가파른 y 방향이 상한을 정한다
- **실제 신경망** → 방향이 수백만 개라 손으로 못 푼다 → Day 4 Momentum · Adam 이 방향마다 걸음 크기를 자동 조절
- ⚠ 학습률을 크게 = 빨리 배운다? → 경계를 넘으면 **발산** — 손실이 nan 이 되면 학습률부터 의심

**기본 사용형태**
```python
f      = lambda p: p[0] ** 2 + 3 * p[1] ** 2
grad_f = lambda p: np.array([2 * p[0], 6 * p[1]])

def gradient_descent(grad, init, lr, steps):
    p = np.array(init, dtype=float)
    history = [p.copy()]
    for _ in range(steps):
        p = p - lr * grad(p)
        history.append(p.copy())
        if np.linalg.norm(p) > 1e6:          # 발산
            break
    return np.array(history)

h = gradient_descent(grad_f, [-4.0, 2.0], lr=0.1, steps=100)   # h[-1] ≈ (0, 0)
```

**상세 학습**

#### 이 교시에서 답하는 질문
오늘 만든 도구로 **학습의 고리 중 "기울기 → 갱신"** 을 처음 직접 돌린다. 함수의 최소점을 **경사하강법**으로 찾고, 학습률이 결과를 어떻게 바꾸는지 — 너무 작으면 느리고, 너무 크면 튀거나 발산하는 이유 — 를 본다.

#### 개념 1 · 경사하강법 — 기울기 반대 방향으로 조금씩
> p ← p − η · ∇f(p)

- 6교시: ∇f 는 가장 가파른 오르막. 그 반대로 아주 조금(학습률 η 만큼) 이동하면 f 가 줄어든다. 이것을 반복하면 최소점에 다가간다.
- 목표 함수 f(x, y) = x² + 3y², 기울기 ∇f = (2x, 6y) — 손으로 미분한 식(해석적 기울기)을 numerical_gradient 와 비교해 확인한다 (최대 오차 약 1.6 × 10⁻¹¹).
- (−4, 2) 에서 학습률 0.1 로 한 번 이동하면 p₁ = (−4, 2) − 0.1 × (−8, 12) = **(−3.2, 0.8)**. 100번이면 거의 (0, 0).

#### 개념 2 · 학습률 — 너무 작으면 느리고, 너무 크면 튄다
![x² + 3y² 위의 경사하강 경로 — 학습률 0.1 은 부드럽게, 0.3 은 y 방향으로 지그재그](assets/fig/nn/d1-gd-paths.svg)

| 학습률 | 30 step 후 f | 일어나는 일 |
|---|---|---|
| 0.01 | 약 5.05 | 너무 작아 아직 멀었다 (느림) |
| 0.1 | 약 2.5 × 10⁻⁵ | 부드럽게 수렴 |
| 0.3 | 약 1.8 × 10⁻⁵ | y 방향으로 부호를 바꾸며 지그재그, 그래도 수렴 |
| 0.35 | 약 3,654 | y 가 커지며 **발산** |

- **왜 그런가**: 이 함수는 y 방향이 x 방향보다 3배 가파르다. 매 step y 는 (1 − 6η) 배가 되는데, |1 − 6η| < 1 이어야 줄어든다 → **0 < η < 1/3**. 가장 가파른 방향이 학습률의 **상한**을 정하고, 그 학습률로는 완만한 x 방향이 느리다.
- 실제 신경망의 손실 지형도 방향마다 경사가 크게 다르다 → Day 4 의 Momentum · Adam 이 이 문제를 다룬다.

#### 코드로 확인
```python
def f(p):      return p[0] ** 2 + 3 * p[1] ** 2
def grad_f(p): return np.array([2 * p[0], 6 * p[1]])
```
- **무엇을 하나**: 목표 함수와, 손으로 미분한 기울기를 정의한다.
- **어떤 개념**: 개념 1 — 해석적 기울기 (2x, 6y).
- **출력**: `numerical_gradient(f, [1.5, -2.0])` 와의 최대 오차 약 `1.6e-11` (일치)

```python
def gradient_descent(grad, init, lr, steps):
    p = np.array(init, dtype=float)
    history = [p.copy()]
    for _ in range(steps):
        p = p - lr * grad(p)
        history.append(p.copy())
    return np.array(history)

h = gradient_descent(grad_f, [-4.0, 2.0], lr=0.1, steps=100)
```
- **무엇을 하나**: 기울기 반대 방향으로 steps 번 이동하며 지나간 위치를 모두 기록한다.
- **어떤 개념**: 개념 1 의 p ← p − η∇f.
- **출력**: `h[1]` = `[-3.2  0.8]`, `h[-1]` ≈ `[0. 0.]`, f ≈ `6.6e-19`

#### 한 번에 정리
- 경사하강 = 기울기 반대 방향으로 학습률만큼 이동, 반복.
- 학습률: 너무 작으면 느림, 너무 크면 지그재그 · 발산. 가장 가파른 방향이 상한을 정한다 (x² + 3y² 는 1/3).
- 오늘 고리의 "기울기 → 갱신" 을 돌렸다 → Day 2 에서 모델 · 손실을 붙여 데이터로 학습한다.
- ⚠ `history.append(p)` 만 하고 `p.copy()` 를 빠뜨리면, p 를 제자리에서 바꿀 때 기록이 모두 같은 배열이 된다.
