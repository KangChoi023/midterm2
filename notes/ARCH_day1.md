## Day 1 — 내 컴퓨터를 열어본다

### 1교시 · 오프닝

**키워드**: `4대 부품`, `3일의 지도`, `인출-해석-실행`

**개요**: 3일 과정의 도착점과 지도. Day 1 부품(눈에 보이는 것) → Day 2 숫자(부품 안에 담기는 것) → Day 3 CPU가 명령을 실행하는 순간.

**핵심 내용**

#### 3일의 도착점
> CPU 시뮬레이터에서 덧셈 프로그램을 명령어 한 줄씩 실행하며 메모리 · 레지스터 값이 바뀌는 것을 짚어 보인다
- **Day 1** → 부품 4가지의 이름 · 역할 · 사양표 읽기
- **Day 2** → 2진수 · 비트/바이트 · ASCII · RGB · 16진수 — 모든 것은 숫자
- **Day 3** → 논리 연산 · 가산기 · 2의 보수 · 플래그 · 명령어 사이클(인출 → 해석 → 실행)

**연결**

### 2교시 · 부품 4가지

**키워드**: `CPU`, `메모리(RAM)`, `저장장치(SSD/HDD)`, `입출력장치`, `메인보드`

**개요**: 본체를 열면 보이는 부품 4가지의 이름과 위치. 역할은 다음 시간부터.

**핵심 용어**
- **메인보드(mainboard)**: 부품들이 꽂히고 서로 연결되는 큰 기판. CPU 가 가운데, 메모리 슬롯이 그 옆에 있다

**핵심 내용**

#### 4대 부품의 생김새와 위치
| 부품 | 생김새 | 위치 |
|---|---|---|
| CPU | 방열판 아래 네모난 칩 | 메인보드 가운데 |
| 메모리(RAM) | 길쭉한 막대 | CPU 바로 옆 슬롯 |
| 저장장치(SSD/HDD) | 네모난 상자 또는 얇은 막대 | 케이블 또는 슬롯으로 연결 |
| 입출력장치 | 키보드 · 마우스 · 모니터 | 본체 바깥 — 케이블 · 단자 |

### 3교시 · CPU와 메모리

**키워드**: `CPU = 손`, `메모리 = 작업대`, `가까워야 빠르다`

**개요**: CPU 는 일하는 손, 메모리는 일할 재료를 펼쳐 두는 작업대. 둘은 가까워야 일이 빠르다.

**핵심 용어**
- **CPU(Central Processing Unit, 중앙처리장치)**: 계산과 명령 처리를 하는 부품. 비유 — 일하는 손
- **메모리(RAM, 주기억장치)**: 지금 쓰는 프로그램 · 데이터를 올려두는 곳. 비유 — 작업대

**핵심 내용**

#### 손과 작업대
> CPU 는 메모리에 올라온 것만 바로 처리할 수 있다
- **CPU** → 계산 · 명령 처리 (손)
- **메모리** → 지금 쓰는 것을 올려두기 (작업대)
- **둘이 붙어 있는 이유** → 손과 작업대가 가까워야 빠르다 — 실제로 메모리 슬롯은 CPU 바로 옆

**연결**
- [C D2·1교시 포인터 기초](#/c/2/1) — "작업대" 위의 칸마다 주소가 있다는 이야기로 이어짐

### 4교시 · 저장장치와 입출력장치

**키워드**: `저장장치 = 창고`, `입출력장치 = 출입구`, `휘발성`, `비휘발성`

**개요**: 저장장치는 꺼도 남는 창고, 입출력장치는 컴퓨터로 드나드는 출입구. 메모리와 저장장치의 차이 = 전원을 끄면 사라지느냐.

**핵심 용어**
- **저장장치(storage, SSD/HDD)**: 전원을 꺼도 파일이 남는 곳. 비유 — 창고
- **입출력장치(I/O device)**: 입력(키보드 · 마우스)과 출력(모니터)으로 컴퓨터에 드나드는 문. 비유 — 출입구
- **휘발성(volatile)**: 전원이 꺼지면 내용이 사라지는 성질 — 메모리(RAM)

**핵심 내용**

#### 메모리 vs 저장장치
> 끄면 사라지는 작업대 vs 꺼도 남는 창고
- **메모리(작업대)** → 끄면 사라짐 · 지금 쓰는 것만
- **저장장치(창고)** → 꺼도 남음 · 오래 보관
- **Ctrl+S** → 작업대(메모리)의 내용을 창고(저장장치)에 옮겨 적는 일
- ⚠ 저장 안 하고 끄면 작업대 위의 내용은 사라진다

#### 4대 부품 비유 완성
- CPU = 손 · 메모리 = 작업대 · 저장장치 = 창고 · 입출력장치 = 출입구

### 5교시 · 부품이 주고받는 것

**키워드**: `데이터 흐름`, `로딩`, `저장장치 → 메모리 → CPU → 화면`

**개요**: 프로그램이 화면에 뜨기까지 데이터가 지나가는 길을 4단계로 따라간다.

**핵심 내용**

#### 데이터의 길 4단계
> 저장장치 → 메모리 → CPU → 출력
- **1 꺼낸다** → 창고(저장장치)에 보관된 프로그램
- **2 올린다** → 작업대(메모리)에 — 이것이 "로딩"
- **3 처리한다** → 손(CPU)이 명령을 계산
- **4 보여준다** → 출입구(모니터)로 결과

**연결**
- [OS D2·3교시 execve()와 wait()](#/os/2/3) — "꺼내서 메모리에 올리는" 일을 운영체제가 하는 방법

### 6교시 · 사양표 읽는 법

**키워드**: `GHz`, `코어(core)`, `GB`, `사양표`

**개요**: 판매 페이지 사양표의 숫자를 비유로 읽는다 — GHz 는 손의 속도, 코어는 손의 개수, GB 는 작업대 넓이 · 창고 크기.

**핵심 용어**
- **GHz(기가헤르츠)**: CPU 가 1초에 일하는 횟수(클럭). 클수록 빠르다 — 손이 움직이는 속도
- **코어(core)**: CPU 안의 일하는 단위. 여러 개면 여러 일을 동시에 — 손의 개수
- **GB(기가바이트)**: 크기 단위. 메모리면 한 번에 올려둘 양(작업대 넓이), 저장장치면 보관할 양(창고 크기)

**핵심 내용**

#### 사양표 한 줄씩
| 줄 | 찾을 숫자 | 비유 |
|---|---|---|
| CPU | GHz · 코어 수 | 손의 속도 · 손의 개수 |
| 메모리 | GB | 작업대 넓이 |
| 저장장치 | GB · SSD/HDD | 창고 크기 |
- ⚠ 같은 GB 라도 메모리 GB 와 저장장치 GB 는 뜻이 다르다 (작업대 vs 창고)

### 7교시 · 시스템 정보

**키워드**: `시스템 정보`, `내 사양표`

**개요**: 내 컴퓨터의 시스템 정보 화면에서 CPU · RAM · 저장장치 숫자를 찾아 사양표에 옮긴다.

**핵심 내용**

#### 시스템 정보에서 찾을 것
- **CPU** → 이름 · 속도(GHz) · 코어 수
- **RAM** → 크기(GB)
- **저장장치** → 크기(GB) · 종류(SSD/HDD)
