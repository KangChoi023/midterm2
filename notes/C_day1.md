## Day 1 — 빌드 · 자료형 · 제어문 · 함수

### 1교시 · 개발환경과 첫 컴파일

**키워드**: `gcc`, `a.out`, `-o`, `컴파일 언어`, `main 반환값`, `종료 코드`, `echo $?`, `int main(void)`, `#include <stdio.h>`, `implicit declaration`, `-Wall -Wextra`, `-g`, `-O2`, `\n`, `\0`

**개요**: Python 은 소스를 바로 실행하지만 C 는 **소스(.c)를 실행파일로 번역(컴파일)한 뒤 실행**한다. 1교시는 그 차이를 `hello.c` 로 직접 겪는다 — `gcc` 로 컴파일하고, 이름을 안 주면 `a.out` 이 생기며, 소스를 고쳐도 다시 컴파일하기 전까지 결과가 그대로라는 것. 그리고 `main` 이 돌려준 값이 **종료 코드**로 셸(`$?`)까지 전달된다는 것, 헤더를 빼면 컴파일러가 함수 모양을 몰라 에러가 난다는 것을 확인한다.

**핵심 용어**
- **컴파일(compile)**: 사람이 쓴 소스 코드를 CPU 가 실행할 기계어 파일로 번역하는 일. C 는 "번역 → 실행" 두 단계라 소스를 고치면 다시 번역해야 한다.
- **실행파일**: 컴파일 결과물. `./이름` 으로 실행한다 (`./` = 현재 폴더).
- **종료 코드(exit code)**: 프로그램이 끝나며 운영체제에 남기는 정수. `main` 의 `return` 값이 그대로 쓰인다. `0` = 성공, 그 외 = 실패라는 약속.
- **`$?`**: 셸 변수. 직전에 끝난 프로그램의 종료 코드. 셸 스크립트·Makefile·systemd 가 이 값으로 성공/실패를 판단한다.
- **헤더 파일(`.h`)**: "이런 함수가 있다" 는 **선언**을 모아 둔 파일. `#include` 로 소스에 붙여 넣는다.
- **암시적 선언(implicit declaration)**: 선언 없이 함수를 부른 것. 컴파일러가 인자·반환 타입을 검사할 수 없어 C99 이후 에러.
- **경고 옵션**: `-Wall`(흔한 실수 경고 묶음), `-Wextra`(추가 경고). 오늘부터 항상 켜고 **경고 0개**가 목표.

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `gcc` | `gcc [옵션] 소스.c -o 이름` | C 소스를 컴파일해 실행파일을 만든다. `-o` 없으면 `a.out`. |
| `printf` | `int printf(const char *fmt, ...);` | 서식 문자열대로 화면(stdout)에 출력. `<stdio.h>` 필요. |
| `echo $?` | `echo $?` | 직전 프로그램의 종료 코드를 출력. |

**예제 코드가 하는 일**

| 예제 | 하는 일 |
|---|---|
| 1-1 `hello.c` | `Hello, C!` 를 출력하고 0 을 반환하는 첫 프로그램. `a.out` / `-o hello` 로 각각 빌드해 본다 |
| 1-2 `exitcode.c` | "센서 초기화 실패" 출력 후 `return 7` → `echo $?` 로 종료 코드 7 확인 |
| 1-3 `nohdr.c` | `#include <stdio.h>` 없이 `printf` 호출 → `implicit declaration` 에러 재현 |

**핵심 내용**

#### 컴파일과 실행
> C 는 컴파일 언어 — 소스(`.c`)를 고치면 다시 컴파일해야 실행 파일이 바뀐다
- **`gcc a.c`** → 실행 파일 이름 **`a.out`** (`-o 이름` 이 없을 때)
- **`-Wall -Wextra`** → 흔한 실수 경고 (하루 종일 켠다)
- **`-g`** → gdb 용 디버그 정보 / **`-O2`** → 최적화
- **`\n`** → 줄바꿈 **한 문자** / **`\0`** → 문자열 끝(널)

#### main 과 종료 코드
> `main` 의 반환값이 프로그램의 종료 코드
- **`return 0`** → 정상, 그 외 → 비정상
- **확인** → 셸에서 `echo $?`
- **쓰는 곳** → 스크립트 · Makefile · systemd 가 이 값으로 성공/실패 판단 (Linux 서비스 감시에서 다시 나옴)
- **`int main(void)`** → `void` = 인자를 받지 않는다

#### 헤더 = 선언
> `#include` 로 함수 선언을 가져와야 컴파일러가 호출을 확인할 수 있다
- **`#include <stdio.h>`** → `printf` 선언
- ⚠ 빠뜨리면 → **implicit declaration** (C99 이후 에러)
- **선언/정의 구분** → 3교시에서 정확히

**기본 사용형태**
```bash
gcc -Wall -Wextra -g -o hello hello.c && ./hello
echo $?          # main 이 돌려준 종료 코드
```

### 2교시 · 빌드 과정 해부

**키워드**: `전처리 -E .i`, `컴파일 -S .s`, `어셈블 -c .o`, `링크`, `libc`, `nm`, `U / T`, `undefined reference`, `링크 에러`, `-lm`, `puts`, `objdump -d`, `-O0 -O2 -Os`

**개요**: `gcc hello.c` 한 줄은 사실 **네 단계(전처리 → 컴파일 → 어셈블 → 링크)** 를 한 번에 돌린 것이다. 2교시는 각 단계를 옵션으로 멈춰 세워 산출물(`.i .s .o`)을 직접 열어 본다. 이걸 알아야 에러 메시지가 **어느 단계에서** 났는지 구분할 수 있다 — 특히 "컴파일은 됐는데 `undefined reference`" 는 **링크 단계**의 에러다. 덤으로 컴파일러가 코드를 그대로 번역하지 않는다는 것(`printf` → `puts`, `-O2` 최적화)도 본다.

**핵심 용어**
- **전처리(preprocess)**: `#include` 는 그 파일 내용을 그 자리에 붙여 넣고, `#define` 은 글자를 치환한다. 결과 `.i` (6줄 → 800줄).
- **컴파일(좁은 뜻)**: 전처리된 C 를 **어셈블리**(`.s`, 사람이 읽을 수 있는 CPU 명령)로 번역.
- **어셈블**: 어셈블리를 기계어 **오브젝트 파일**(`.o`)로. 아직 다른 함수의 주소는 모른다.
- **링크(link)**: 여러 `.o` 와 라이브러리(libc 등)를 합쳐 비어 있던 주소를 채우고 실행파일을 만든다.
- **심볼(symbol)**: 함수·전역 변수의 이름. `nm` 에서 `U`(undefined, 남이 채워 줘야 함) / `T`(text, 여기 코드 있음).
- **`undefined reference`**: 선언은 있는데 **정의(본문)를 어느 `.o`/라이브러리에서도 못 찾은** 링크 에러.
- **최적화 수준**: `-O0`(그대로, 디버깅용) / `-O2`(빠르게) / `-Os`(작게, 임베디드).

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `gcc -E / -S / -c` | `gcc -E a.c -o a.i` 등 | 전처리 / 컴파일 / 어셈블 단계에서 멈춘다. |
| `nm` | `nm 파일.o` | 오브젝트·실행파일의 심볼 목록(`U`/`T`) 보기. |
| `objdump -d` | `objdump -d 파일.o` | 기계어를 어셈블리로 역변환(디스어셈블). |
| `wc -l` / `diff` | `wc -l a b` / `diff a b` | 줄 수 세기 / 두 파일 차이 비교 (산출물 비교용). |

**예제 코드가 하는 일**

| 예제 | 하는 일 |
|---|---|
| 2-1 | `hello.c` 를 `-E → -S → -c → 링크` 로 한 단계씩 빌드, `wc -l` 로 `.i` 가 800줄이 된 것 확인 |
| 2-2 | `hello.s` 를 열어 `printf` 가 `call puts@PLT` 로 바뀐 것 확인 |
| 2-3 | `nm hello.o` 에서 `U puts`(미해결) / `T main`, 링크 후 `puts@GLIBC` 로 연결된 것 확인 |
| 2-4 `4_link_err.c` | 선언만 있고 정의 없는 `read_sensor()` 호출 → `-c` 는 성공, 링크에서 `undefined reference` |
| 2-5 | `-O0` vs `-O2` 어셈블리를 `wc -l`·`diff` 로 비교 (프레임 설정 `pushq %rbp` 가 사라짐) |

**핵심 내용**

#### gcc 4단계
> `gcc` 한 줄 = 전처리 → 컴파일 → 어셈블 → 링크

| 단계 | 옵션 | 산출물 | 하는 일 |
|---|---|---|---|
| 전처리 | `-E` | `.i` | `#include`·`#define` 풀기 (6줄 → 800줄) |
| 컴파일 | `-S` | `.s` | C → 어셈블리 |
| 어셈블 | `-c` | `.o` | 어셈블리 → 기계어(오브젝트) |
| 링크 | (없음) | 실행파일 | `.o` + 라이브러리(libc) 합치기 |

- **`objdump -d`** → 오브젝트의 기계어를 어셈블리로 역변환
- **컴파일러는 그대로 번역하지 않음** → 서식 없는 `printf("..\n")` 가 `puts` 로 바뀜

#### 링크와 심볼
> 링커는 `.o` 들의 이름(심볼)을 이어 붙인다 — 못 찾으면 링크 에러
- **`nm` 의 `U`** → undefined, 아직 미해결 (링커가 채움)
- **`nm` 의 `T`** → text, 여기에 코드가 있음
- **링크 후에도 `U puts@GLIBC…`** → 실행할 때 libc.so 에서 찾기로 연결됨 (동적 링크)
- **`undefined reference`** → **링크 에러**: 선언은 있는데 정의를 어느 `.o` 에서도 못 찾음
- **원인** → 이름 오타 · `.c` 누락 · `-lm` 누락
- **단서** → `-c` 까지는 성공한다

#### 최적화 단계
> 같은 코드라도 `-O` 수준에 따라 기계어가 달라진다
- **`-O0`** → 그대로 번역
- **`-O2`** → 프레임 설정 제거 등으로 짧아짐
- **임베디드 릴리스** → `-O2` / `-Os`

**기본 사용형태**
```bash
gcc -E hello.c -o hello.i     # ① 전처리
gcc -S hello.i -o hello.s     # ② 컴파일
gcc -c hello.s -o hello.o     # ③ 어셈블
gcc hello.o  -o hello         # ④ 링크
nm hello.o                    # U puts / T main
```

### 3교시 · 헤더/소스 분리와 Makefile

**키워드**: `선언 vs 정의`, `.h / .c`, `헤더 가드 #ifndef #define #endif`, `redefinition`, `"sensor.h" vs <stdio.h>`, `typedef struct`, `Makefile`, `타깃: 의존파일`, `탭`, `missing separator`, `$(CC) $(CFLAGS)`, `수정 시각`, `touch`, `make clean`, `경고 읽기`

**개요**: 프로그램이 커지면 파일 하나에 다 넣을 수 없다. 3교시는 코드를 **선언(`.h`) / 정의(`.c`) / 사용(`main.c`)** 세 파일로 나누고, 같은 헤더가 두 번 들어와도 깨지지 않게 **헤더 가드**를 붙인다. 파일이 여러 개가 되면 매번 `gcc` 를 길게 칠 수 없으니 **Makefile** 로 "무엇을 무엇으로 만드는지" 적어 두고, make 가 **수정 시각**을 비교해 **바뀐 파일만 다시 컴파일**하는 것을 확인한다. 마지막으로 경고 메시지 읽는 법을 익힌다.

**핵심 용어**
- **선언(declaration)**: "이런 이름과 타입이 있다" 는 약속 (함수 원형, `extern` 변수). 여러 번 나와도 된다.
- **정의(definition)**: 실제 본문·메모리를 만드는 것. 프로그램 전체에서 **한 번만**.
- **헤더 가드(include guard)**: `#ifndef X_H / #define X_H / … / #endif`. 같은 헤더가 두 번 include 돼도 내용은 한 번만 들어가게 하는 장치.
- **Makefile 규칙**: `타깃: 의존파일들` 다음 줄에 **탭**으로 시작하는 명령. 의존파일이 타깃보다 새로우면 명령을 실행한다.
- **`make clean`**: 관례상 산출물(`.o`, 실행파일)을 지우는 타깃.
- **`touch`**: 파일 내용은 그대로 두고 **수정 시각만 지금으로** 바꾸는 명령 (make 재빌드 실험용).

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `make` | `make [타깃]` | Makefile 의 규칙대로 필요한 것만 다시 빌드. 타깃 생략 시 첫 규칙. |
| `touch` | `touch 파일` | 수정 시각 갱신 → make 가 "바뀌었다" 고 판단. |
| `typedef struct {…} 이름;` | `typedef struct { double t; int h; } Reading;` | 여러 값을 한 묶음 타입으로 (자세히는 Day 3). |

**핵심 내용**

#### 선언 · 정의 · 헤더 가드
> 선언은 `.h`, 정의(본문)는 `.c` — 헤더는 여러 번 include 돼도 안전해야 한다
- **헤더에 두는 것** → 함수 원형 · 구조체/typedef · 매크로
- **헤더 가드** → 중복 include 방지 (`#ifndef X_H` / `#define X_H` / `#endif`)
- **반복돼도 되는 것** → 함수 선언 / **한 번만** → struct · typedef 정의
- **실제로 겹치는 순간** → `a.h` 와 `b.h` 가 같은 공용 헤더를 include 할 때
- **`"my.h"`** → 현재 폴더 먼저 / **`<stdio.h>`** → 시스템 경로만

#### Makefile
> `타깃: 의존파일` + 탭 명령 — 수정 시각을 비교해 바뀐 것만 다시 만든다
- **명령 줄** → **탭**으로 시작 (공백이면 `missing separator`)
- **변수** → `$(CC)`
- **헤더도 의존성에 적기** → 안 적으면 오래된 `.o` 가 링크되어 "분명 고쳤는데 안 바뀌는" 버그
- **`touch sensor.c`** → `sensor.o`, `app` 만 다시
- **`touch sensor.h`** → `main.o`, `sensor.o`, `app` 전부 다시

#### 경고 읽기
> 경고는 실제 버그의 신호 — 경고 0개가 제출 조건
- **형식** → `파일:줄:열: warning: 내용 [옵션이름]`

**기본 사용형태**
```c
#ifndef SENSOR_H
#define SENSOR_H
int is_alert(Reading r);       // 선언만
#endif
```
```make
CC = gcc
CFLAGS = -Wall -Wextra -O2
app : main.o sensor.o
	$(CC) $(CFLAGS) -o app main.o sensor.o
main.o : main.c sensor.h
	$(CC) $(CFLAGS) -c main.c
clean :
	rm -f *.o app
```

### 4교시 · 자료형과 메모리 표현

**키워드**: `sizeof`, `%zu`, `size_t`, `char short int long`, `포인터 크기`, `stdint.h`, `uint8_t int32_t`, `고정폭 타입`, `오버플로`, `wrap-around`, `undefined behavior`, `2의 보수`, `부호 비트`, `리틀 엔디안`, `LSB`, `빅 엔디안`

**개요**: 변수는 결국 **몇 바이트의 비트 묶음**이고, 자료형은 "몇 바이트를 어떤 규칙으로 읽을지" 의 약속이다. 4교시는 ① 타입별 크기를 예측하고 `sizeof` 로 확인하며 플랫폼마다 크기가 달라 임베디드는 **고정폭 타입**을 쓴다는 것, ② 값이 범위를 넘치면 **잘린다**는 것, ③ 같은 비트도 signed/unsigned 에 따라 다르게 읽힌다는 것(**2의 보수**), ④ 여러 바이트 값이 메모리에 **거꾸로(리틀 엔디안)** 놓인다는 것을 본다. 규칙: **예측 먼저 쓰고 실행**.

**핵심 용어**
- **`sizeof`**: 타입·변수의 바이트 수를 컴파일 시간에 알려 주는 연산자. 결과 타입은 `size_t`(부호 없는 정수), 서식은 `%zu`.
- **고정폭 정수 타입**: `<stdint.h>` 의 `uint8_t`, `int16_t`, `uint32_t` … 이름에 비트 수가 박혀 있어 어느 플랫폼에서도 크기가 같다.
- **오버플로(overflow)**: 값이 타입의 범위를 넘는 것. unsigned 는 **감김**(모듈러), signed 는 **정의되지 않은 동작(UB)**.
- **정의되지 않은 동작(undefined behavior)**: C 표준이 결과를 정하지 않은 경우. 컴파일러가 무엇을 해도 되므로 절대 의존하지 않는다.
- **2의 보수(two's complement)**: 음수 표현 방식. 최상위 비트가 1이면 음수, 8비트 기준 값 = unsigned 값 − 256.
- **엔디안(endianness)**: 여러 바이트 값을 메모리에 놓는 순서. **리틀 엔디안** = 낮은 주소에 낮은 바이트(LSB) (x86, ARM, ESP32). **빅 엔디안** = 반대 (네트워크 바이트 순서).

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `sizeof` | `sizeof(타입)` / `sizeof 변수` | 바이트 수. `printf("%zu", sizeof(int))`. |
| `%02X` | `printf("%02X", byte)` | 16진수 두 자리(빈자리 0)로 바이트 출력. |
| `(unsigned char *)&v` | 형변환 + 주소 | 변수 `v` 를 바이트 단위로 들여다보기 (Day 2 포인터에서 본격). |

| 예제 | 하는 일 |
|---|---|
| 4-1 `1_sizeof.c` | 9개 타입의 `sizeof` 출력 (x86-64: `char 1 · short 2 · int 4 · long 8 · … · int * 8`) |
| 4-2 `2_endian.c` | `int v = 0x11223344` 의 바이트를 낮은 주소부터 출력 → `44 33 22 11` |

**핵심 내용**

#### 타입 크기
> 크기는 플랫폼마다 다르다 — 임베디드는 고정폭 타입
- **x86-64 Linux** → `char 1 / short 2 / int 4 / long 8 / float 4 / double 8 / 포인터 8`
- ⚠ `long` → Windows 에서 **4** / 포인터 → 32비트 MCU 에서 **4**
- **고정폭 타입** → `<stdint.h>` 의 `uint8_t`, `int32_t` …
- **`sizeof` 출력** → `%zu` (size_t)
- **범위** → `uint8_t` **0~255**, `int8_t` **−128~127**

#### 오버플로와 비트 해석
> 같은 비트도 타입에 따라 다른 값 — 범위를 넘으면 잘리거나 정의되지 않는다
- **unsigned 넘침** → 감김 (`uint8_t` 250+10 = **4**)
- ⚠ **signed 넘침** → 정의되지 않은 동작 (127+1 → −128 에 의존 금지)
- **`int 300` → `unsigned char`** → **44** (하위 1바이트 0x2C)
- **`11001000`** → unsigned **200** = signed **−56** (2의 보수: 값 − 256)

#### 엔디안
> 여러 바이트 값을 메모리에 놓는 순서
- **리틀 엔디안 (x86, ARM)** → 낮은 주소에 **낮은 바이트(LSB)**
- **`0x11223344`** → 메모리에 `44 33 22 11`
- **네트워크** → 빅 엔디안 (반대)
- ⚠ 메모리 덤프 · 시리얼로 받은 바이트가 "거꾸로" 보이는 이유 → 통신 프로토콜에서 항상 확인

**기본 사용형태**
```c
printf("%zu %zu\n", sizeof(int), sizeof(long));     // 4 8
uint8_t a = 250; a += 10;                           // 4
int v = 0x11223344;
unsigned char *p = (unsigned char *)&v;
printf("%02X %02X\n", p[0], p[1]);                  // 44 33
```

### 5교시 · 형변환 · 오버플로 · 실수 정밀도

**키워드**: `암시적 변환`, `signed ↔ unsigned 비교`, `-1 < 1u`, `-Wsign-compare`, `size_t`, `정수 승격`, `sizeof(c+1)`, `정수 나눗셈`, `7/2`, `%`, `9.0`, `(double) 캐스팅 위치`, `0.1+0.2`, `fabs`, `오차 비교`, `-lm`, `(int)3.99`

**개요**: C 는 서로 다른 타입이 한 식에 섞이면 **말없이(암시적으로) 변환**한다. 5교시는 그 규칙이 만드는 함정 네 가지를 직접 밟는다 — ① `int` 와 `unsigned` 를 비교하면 음수가 거대한 양수가 되는 것, ② `char` 도 계산하는 순간 `int` 가 되는 **정수 승격**, ③ 정수끼리 나누면 소수점이 **버려지는** 것과 캐스팅 위치의 중요성, ④ 실수는 정확히 표현되지 않아 `==` 로 비교하면 안 되는 것.

**핵심 용어**
- **암시적 형변환(implicit conversion)**: 프로그래머가 쓰지 않아도 컴파일러가 타입을 맞추는 변환. 비교·산술에서 "더 넓은/부호 없는" 쪽으로 맞춘다.
- **명시적 형변환(캐스팅)**: `(double)x` 처럼 직접 쓰는 변환. **이미 계산이 끝난 값**에 적용된다.
- **정수 승격(integer promotion)**: `char`, `short`, `uint8_t` 처럼 `int` 보다 작은 타입은 연산에 들어가는 순간 `int` 로 바뀐다.
- **정수 나눗셈**: 두 피연산자가 모두 정수면 결과도 정수(소수점 **버림**). `%` 는 나머지.
- **부동소수점 오차**: `0.1` 같은 값은 2진수로 정확히 표현할 수 없어 아주 작은 오차가 생긴다 → 같음 비교는 "차이가 충분히 작은가" 로.

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `fabs` | `double fabs(double x);` | 실수 절댓값. 오차 비교 `fabs(a-b) < 1e-9`. `<math.h>` + 링크 `-lm`. |
| `-lm` | `gcc … -lm` | 수학 라이브러리(libm) 링크. 빼면 `undefined reference to 'fabs'`(링크 에러). |
| `%.20f` / `%u` | `printf("%.20f", a)` | 소수점 20자리까지(오차 눈으로 보기) / unsigned 출력. |

**예제 코드가 하는 일**

| 예제 | 하는 일 |
|---|---|
| 5-1 `1_promo.c` | `-1 < 1` 은 1, `-1 < 1u`·`-1 < sizeof(int)` 는 0, `(unsigned)-1` = 4294967295 출력 + `-Wsign-compare` 경고 |
| 5-2 `2_promo2.c` | `sizeof(c)`=1, `sizeof(c+1)`=4, `c+1` 을 `%c`/`%d` 로 → `B 66` |
| 5-3 `3_intdiv.c` | `7/2`=3, `7/2.0`=3.5, `7%2`=1, 섭씨 26 → 화씨 `78.0`(틀림) vs `78.8`(맞음) |
| 5-4 `4_fp.c` | `0.1+0.2 == 0.3` 은 0, `%.20f` 로 오차 확인, `fabs` 비교는 1, `(int)3.99`=3 |

**핵심 내용**

#### signed / unsigned 섞기
> `int` 와 `unsigned` 를 섞으면 `int` 가 unsigned 로 바뀐다
- **`-1 < 1u`** → **거짓(0)** (−1 → 4294967295)
- **`-1 < sizeof(int)`** → 거짓 (`sizeof` 는 `size_t` = unsigned)
- ⚠ 배열 길이와 음수 인덱스 비교에서 자주 터짐
- **경고** → `-Wsign-compare` (`-Wextra` 에 포함)

#### 정수 승격
> `int` 보다 작은 타입은 연산하면 `int` 가 된다
- **`sizeof(c + 1)`** (c 는 char) → **4**
- **`uint8_t a += 10`** → int 로 계산한 뒤 8비트로 잘라 넣음

#### 정수 나눗셈과 실수 계산
> 정수끼리 나누면 소수점 아래를 버린다 — 실수가 하나라도 있어야 실수 계산
- **`7/2`** → **3**
- **`c*9/5+32`** (c=26) → **78.0** (왼쪽부터 정수 계산)
- **고치기** → `c * 9.0 / 5 + 32` = **78.8**
- ⚠ `(double)(c*9/5)` → 이미 잘린 뒤라 소용없음
- ⚠ c=25 면 둘 다 77.0 으로 우연히 맞음 → **테스트 값 하나로 안심 금지**
- **`(int)3.99`** → **3** (버림, 반올림 아님)

#### 실수 비교
> 실수는 2진수로 정확히 표현되지 않아 `==` 로 비교하지 않는다
- ⚠ `0.1 + 0.2 != 0.3`
- **비교** → `fabs(a - b) < 오차`
- **`<math.h>`** → 링크에 `-lm`

**기본 사용형태**
```c
printf("%d\n", -1 < 1u);                   // 0
double f = c * 9.0 / 5 + 32;               // 78.8
if (fabs(a - 0.3) < 1e-9) { ... }          // 실수 비교
```

### 6교시 · 연산자와 제어문

**키워드**: `= vs ==`, `& vs &&`, `시프트 우선순위`, `괄호`, `switch`, `case = 점프 목적지`, `break`, `fall-through`, `// fall through`, `-Wimplicit-fallthrough`, `case 'y': case 'Y':`, `default`, `if-else if`, `const char *`, `do-while`, `continue`, `%`, `소수 판별 i*i<=n`

**개요**: 연산자와 제어문 자체는 Python 과 비슷하지만, C 에는 **한 글자 차이로 전혀 다르게 동작하는 함정**이 있다. 6교시는 그 네 가지(`=`/`==`, `&`/`&&`, 시프트 우선순위, `switch` 의 `break` 누락)를 직접 밟고 모두 `-Wall -Wextra` 가 잡아 준다는 것을 확인한다. 특히 `switch` 의 `case` 는 블록이 아니라 **점프 목적지**라서 `break` 를 만날 때까지 아래로 흘러간다(fall-through). 그 위에 어제 Python 의 온도 판정 `level()` 을 C 로 옮기고, 반복문으로 소수를 판별한다.

**핵심 용어**
- **대입(`=`) vs 비교(`==`)**: `if (x = 5)` 는 x 에 5 를 넣고 그 값(5, 참)으로 판단 → 항상 참.
- **비트 AND(`&`) vs 논리 AND(`&&`)**: `&` 는 비트마다 AND (`2 & 4` = 0), `&&` 는 참/거짓 판단 (`2 && 4` = 1).
- **연산자 우선순위**: `+` 가 `<<` 보다 먼저 → `1 << 3 + 1` = `1 << 4` = 16. 시프트에는 **항상 괄호**.
- **fall-through**: `switch` 에서 `break` 가 없어 다음 `case` 로 계속 실행되는 것. 의도라면 `// fall through` 주석으로 표시.
- **`do-while`**: 조건을 **나중에** 검사하는 반복 → 최소 한 번 실행 (메뉴 루프).
- **`break` / `continue`**: 가장 가까운 반복·switch 하나 탈출 / 이번 반복만 건너뛰고 다음으로.

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `switch` | `switch (정수) { case 상수: …; break; default: … }` | 정수 값에 따라 여러 갈래로 점프. |
| `do-while` | `do { … } while (조건);` | 최소 한 번 실행하는 반복. |
| `const char *` 반환 | `const char *level(double t)` | 문자열 리터럴을 돌려주기 (Day 2 에서 포인터로 설명). |

**예제 코드가 하는 일**

| 예제 | 하는 일 |
|---|---|
| 6-1 `1_pitfalls.c` | `if (x = 5)` 항상 참, `2&4`=0 vs `2&&4`=1, `1<<3+1`=16 vs `(1<<3)+1`=9 + 각 경고 확인 |
| 6-2 `2_switch.c` | `level = 2` 에서 `break` 없는 `case 2` 가 `case 3` 까지 흘러 `COLD NORMAL` 출력 |

**핵심 내용**

#### 연산자 4대 함정
> 전부 `-Wall -Wextra` 가 잡아 준다
- ⚠ **`=` vs `==`** → `if (x = 5)` 는 항상 참
- ⚠ **`&` vs `&&`** → `2 & 4` = 0, `2 && 4` = 1
- ⚠ **시프트 우선순위** → `1 << 3 + 1` = **16** → 괄호 필수
- ⚠ **`switch` 의 `break` 누락** → 아래 case 로 이어짐
- **비트 연산** → Day 3 레지스터 제어의 핵심 → 지금부터 시프트에 괄호 습관

#### switch 와 fall-through
> `case` 는 블록이 아니라 점프 목적지 — `break` 를 만날 때까지 계속 실행
- **경고** → `-Wextra` 의 `-Wimplicit-fallthrough`
- **의도한 fall-through** → `// fall through` 주석 (gcc 가 인식해 경고를 끔)
- **값 여러 개에 처리 하나** → `case 'y': case 'Y': ok = 1; break;` (빈 case 는 경고 없음)

#### 반복 제어
> 루프를 도는 방식과 빠져나가는 방식
- **`do { } while (조건);`** → **최소 한 번** 실행 (메뉴 루프)
- **`break`** → 가장 가까운 루프/switch **하나**만 탈출
- **`continue`** → 이번 반복만 건너뜀
- **`x % 2 == 0`** → 짝수
- **소수 판정** → `i * i <= n` 까지만 (√n)

**기본 사용형태**
```c
switch (n) {
    case 1: printf("one "); break;
    case 2: printf("two "); break;
    default: printf("other ");
}
do { scanf("%d", &sel); } while (sel != 0);
for (int i = 2; i * i <= n; i++) if (n % i == 0) return 0;
```

### 7교시 · 함수와 스코프

**키워드**: `call by value`, `복사본`, `함수 원형`, `지역 변수`, `스택 프레임`, `재귀`, `LIFO`, `스택 오버플로`, `Segmentation fault`, `static 지역 변수`, `데이터 영역`, `한 번만 초기화`, `static 함수/전역`, `internal linkage`, `인자 평가 순서`, `부수효과`, `%*s`

**개요**: 함수에 값을 넘기면 무슨 일이 일어나는가? 7교시는 C 의 함수 호출을 메모리 관점에서 본다 — ① 인자는 **복사본**이라 함수 안에서 바꿔도 원본은 그대로(→ Day 2 포인터의 동기), ② 호출마다 **스택 프레임**이 쌓이고 끝나면 거꾸로 사라지며(LIFO), 재귀가 너무 깊으면 스택이 넘친다, ③ `static` 변수는 스택 밖(**데이터 영역**)에 살아 호출 사이에도 값이 유지된다, ④ 함수 인자의 **평가 순서는 정해져 있지 않다**.

**핵심 용어**
- **값 전달(call by value)**: 인자의 값을 복사해 매개변수에 넣는 방식. C 의 유일한 전달 방식 (주소를 넘기는 것도 "주소 값" 의 복사).
- **함수 원형(prototype)**: `int fact(int n);` 처럼 본문 없이 이름·인자·반환 타입만 적은 선언.
- **스택 프레임(stack frame)**: 함수 한 번 호출에 필요한 지역 변수·인자·돌아갈 주소를 담는 스택 공간. 함수가 끝나면 사라진다.
- **LIFO**: Last In First Out. 가장 나중에 쌓인 프레임이 가장 먼저 사라진다.
- **스택 오버플로**: 프레임이 스택 크기를 넘는 것 → 세그폴트. PC 스택 ~8MB, ESP32 태스크 스택은 수 KB.
- **`static` 지역 변수**: 함수 안에 있지만 **데이터 영역**에 살고, 첫 호출 전에 한 번만 초기화되어 호출 사이 값 유지.
- **내부 연결(internal linkage)**: 파일 범위 함수·전역에 붙인 `static` 의 뜻 — "이 `.c` 밖에서는 안 보임" (이름 충돌 방지).
- **부수효과(side effect)**: 값을 돌려주는 것 말고 상태를 바꾸는 것(전역/static 변경, 출력 등).

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `static` | `static int id = 0;` | 지역: 값 유지 / 파일 범위: 이 파일 전용. |
| `%*s` | `printf("%*s", 폭, "")` | 폭을 인자로 받는 서식 → 재귀 깊이만큼 들여쓰기. |

**핵심 내용**

#### 값 전달과 함수 원형
> C 는 값 전달 — 인자는 복사본이다
- **함수 안에서 인자를 바꿔도** → 원본은 그대로
- **원본을 바꾸려면** → 주소를 넘긴다 (Day 2)
- **함수 원형** → 호출보다 위에 선언해야 컴파일러가 타입을 안다
- **반환값 없음** → `void` / `main` 은 `int`

#### 스택 프레임과 재귀
> 지역 변수는 그 호출의 스택 프레임에 있고, 호출이 끝나면 사라진다
- **재귀** → 프레임이 쌓였다가 **LIFO** 로 사라짐 (`fact(3)`: 최대 3프레임)
- ⚠ 너무 깊으면 → **스택 오버플로** (세그폴트)
- **스택 크기** → PC 약 8MB / ESP32 태스크 수 KB
- **임베디드 재귀** → 깊이를 확실히 알 때만

#### static
> 붙는 자리에 따라 수명 또는 보이는 범위를 바꾼다
- **`static` 지역 변수** → 데이터 영역, **한 번만 초기화**, 호출 사이 값 유지
- **함수/전역에 `static`** → **이 파일 전용** (내부 연결)

#### 인자 평가 순서
> 함수 인자를 어느 순서로 계산할지는 정해져 있지 않다
- **`f(next(), next(), next())`** → gcc 에서 `3 2 1`
- ⚠ `printf("%d %d", fact(3), calls)` → calls 가 먼저 읽혀 0 이 나올 수 있음
- **규칙** → 부수효과 있는 호출은 한 식에 여러 번 쓰지 말고 **변수에 먼저 받는다**

**기본 사용형태**
```c
int next_id(void) { static int id = 0; return ++id; }   // 1, 2, 3
int fact(int n) { if (n <= 1) return 1; return n * fact(n - 1); }
int r = fact(3);  printf("%d %d\n", r, calls);          // 먼저 받고 출력
```

### 8교시 · 종합 — 숫자 야구 설계

**키워드**: `숫자 야구`, `srand(time(NULL))`, `rand() % 10`, `중복 없는 난수`, `int ans[3]`, `함수 분리`, `gen_answer read_guess is_valid judge print_result`, `포인터 인자 int *strike`, `&s &b`, `(*strike)++`, `scanf 반환값`, `입력 버퍼 비우기 getchar`, `파일 4개`, `경고 0개`

**개요**: 하루 동안 배운 것(파일 분리·Makefile·제어문·함수·static)을 **숫자 야구 게임** 하나로 묶는다. 서로 다른 세 자리 숫자를 맞히는 게임을 `main.c / game.c / game.h / Makefile` 네 파일로 나누고, 함수마다 책임을 하나씩 준다. 새로 등장하는 것은 난수(`srand`/`rand`), 잘못된 입력에도 죽지 않는 **입력 검증**, 그리고 함수에서 값 두 개를 돌려주기 위한 **포인터 인자**(Day 2 예고)다.

**핵심 용어**
- **의사 난수(pseudo-random)**: `rand()` 는 시드(seed)에서 정해진 수열을 만든다. 같은 시드면 같은 수열 → 시작할 때 `srand(time(NULL))` 로 시드를 바꾼다.
- **입력 버퍼**: 키보드 입력이 쌓이는 곳. `scanf` 가 숫자를 못 읽으면 문자가 버퍼에 **그대로 남아** 다음 `scanf` 도 실패 → 무한 루프.
- **포인터 인자**: 함수가 호출한 쪽의 변수를 직접 바꿀 수 있도록 **변수의 주소**를 받는 매개변수 (`int *strike`). 호출은 `&s`.
- **책임 분리**: 함수 하나 = 일 하나. 파일도 역할별로 나누면 바뀐 파일만 다시 컴파일된다.

**새로 나온 함수·명령**

| 이름 | 기본형 | 용도 |
|---|---|---|
| `srand` | `void srand(unsigned seed);` | 난수 시드 설정. **프로그램 시작 시 한 번**. `<stdlib.h>` |
| `rand` | `int rand(void);` | 0 ~ RAND_MAX 의사 난수. `rand() % 10` → 0~9. |
| `time` | `time_t time(time_t *t);` | 현재 시각(초). `time(NULL)` 을 시드로. `<time.h>` |
| `scanf` | `int scanf(const char *fmt, ...);` | 서식대로 읽고 **성공한 항목 수**를 반환 → `!= 3` 이면 실패. |
| `getchar` | `int getchar(void);` | 한 글자 읽기. 남은 입력을 `'\n'`/`EOF` 까지 버릴 때. |

**핵심 내용**

#### 정답 만들기 — 난수
> 시드는 시작할 때 한 번, 중복 없는 세 수는 "뽑고 → 비교 → 넣기"
- **`srand((unsigned)time(NULL))`** → **프로그램 시작 시 한 번**
- **`rand() % 10`** → 0~9
- **중복 없는 세 개** → 뽑고 → 앞에 있던 것과 비교 → 없으면 넣기
- **정답** → `int ans[3]` 배열

#### 함수 나누기와 포인터 인자
> 함수는 책임 하나 — 두 값을 돌려주려면 포인터 인자
- **함수 분리** → `gen_answer / read_guess / is_valid / judge / print_result`
- **`judge`** → 숫자 같고 `i == j` → strike, 숫자만 같으면 → ball
- **두 값 반환** → `int *strike, int *ball` (호출: `judge(ans, g, &s, &b)`)
- **`const int g[3]`** → 읽기만 한다는 표시
- **종료 조건** → `s == 3`

#### 입력 검증
> 잘못된 입력에도 죽지 않고 다시 묻는다
- **`scanf(...) != 3`** → 실패
- **실패하면** → 입력 버퍼를 비우고(`getchar` 반복) 다시 묻기
- ⚠ 안 비우면 → **무한 루프**
- **시험 입력** → `"12"`, `"abc"`, `"1 1 2"` 에서 죽지 않아야 함

#### 파일 분리와 제출 조건
> 책임별로 파일을 나누면 바뀐 파일만 다시 컴파일된다
- **파일** → `main.c / game.c / game.h / Makefile`
- **제출 조건** → **경고 0개**, `make clean && make` 가 처음부터 성공

**기본 사용형태**
```c
srand((unsigned)time(NULL));
if (scanf("%d %d %d", &g[0], &g[1], &g[2]) != 3) {
    int c; while ((c = getchar()) != '\n' && c != EOF) {}
    return 0;
}
(*strike)++;        // 괄호 필수: *strike++ 는 포인터를 옮김
```
